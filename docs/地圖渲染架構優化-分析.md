> 寫於 2026-04-26，對應規格書 v1.0 §3.5 / 需求書 §2.4 + §2.5。
> 分析 commit `1dc24bd`（Phase 2 Task 10 + sub-pixel 平滑拖曳）後的剩餘候選項。

---

## Context

Phase 2 接近尾聲。規格書 §3.5 列出 4 個地圖渲染架構級議題，作為 Phase 3 重構候選。本分析評估**現況下哪些值得做、哪些該延後**，提供決策依據。

**已完成項目**（commit `1dc24bd`）：
- ✅ **sub-pixel 平滑拖曳** — `MainMapRenderer.DecomposeOffset` + `UpdateAllTiles / UpdateParallaxScene / FindClickedTile` 三處同步處理整格 + 小數，原議題「中鍵拖曳整格 snap 體感斷裂」已解決

**剩餘候選**（本分析重點）：
1. SubViewport 重構（Plan B）— 真正 GPU 級 clipping
2. 滑鼠中心 zoom — 可選 feature
3. tile 溢出 MapArea — 視覺裁切議題
4. 慣性滑動 — 已判定不適合 TRPG，跳過

## 五軸分析

### 候選 1 — SubViewport 重構

| 軸 | 內容 |
|---|---|
| **方向** | 將 `MapArea` 從 `Control` 升級為 `SubViewportContainer + SubViewport + MainMapRoot`，把 81 個 TileVisual + ParallaxScene 全部塞進 SubViewport |
| **方式** | 1) 改 `scenes/main.tscn` 的 `MiddleColumn/MapArea` 結構；2) `MainMapRenderer` 與 `CameraController._Input` 的滑鼠座標改用 `subViewport.GetMousePosition()`；3) PlayCardZone 同步搬進 SubViewport（保持與手牌 drag-drop 同 viewport）；4) 訂閱 `MapArea.resized` 同步 SubViewport.size |
| **目標** | tile 在極端 camera offset 下不再溢出 MapArea；為 zoom / shader / post-processing 鋪路 |
| **成果** | GPU 級裁切、可加 shader、未來 zoom feature 可直接 scale `MainMapRoot` |
| **風險** | 🔴 **跨 viewport drag-drop 失效**：HandDock 的卡牌 → PlayCardZone 走 Godot Control drag API（[CardView.cs:98](../scripts/Ui/CardView.cs#L98) `_GetDragData`，[PlayCardZone.cs:100](../scripts/Ui/PlayCardZone.cs#L100) `GetViewport().GuiGetDragData()`），HandDock 與 PlayCardZone 必須同 viewport。緩解：PlayCardZone 也搬進 SubViewport，或 HandDock 跟著搬。<br>🟡 **滑鼠座標重算**：MainMapRenderer 多處 `mb.Position` / `GetLocalMousePosition` 需改 SubViewport 版。<br>🟡 **小地圖 (Task 10)** 不在 SubViewport 內 — 視野框幾何不受影響（讀 `WorldMap.CameraOffset` 抽象座標），但若加 zoom 需自行 scale 計算。<br>🟢 **MoveConfirmDialog 是獨立 Window** — 不受影響。<br>🟢 **ParallaxScene** 已在 MainMap 之下，跟著進 SubViewport 即可。 |

**工時**：4–8 小時（含跨 viewport drag-drop 全套回歸）

---

### 候選 2 — 滑鼠中心 zoom

| 軸 | 內容 |
|---|---|
| **方向** | 滾輪縮放，以滑鼠位置為中心；scale 整個 `MainMapRoot` |
| **方式** | 1) `CameraController._Input` 監聽 `MouseButton.WheelUp/Down`；2) 標準 zoom-to-cursor 公式：先記錄 `mousePos.WorldBefore = ScreenToWorld(zoomBefore)`，套新 zoom 後算 `mousePos.WorldAfter`，把差值加進 `CameraOffset`；3) **勿改 `BaseTileSize`** — Projection 的 yRatio / FarScale 都依賴 BaseTileSize，改了會破透視 |
| **目標** | 細看遠處地塊；玩家可手動拉近觀察事件標記 |
| **成果** | 縮放層獨立於 Projection，視覺保持一致 |
| **風險** | 🟡 **規格未要求** — 需求書 / 規格書都沒列為 must-have。做了反而讓 UI 多一個操作維度。<br>🟡 **小地圖視野框尺寸需跟著 scale** — 5×5 視野在 zoom 後可能變 7×7 或 3×3，視野框幾何要重算。<br>🟢 **必須先有 SubViewport** — scale `MainMapRoot` 在無 SubViewport 環境下會超出 Control bounds 蓋到 LeftPanel/RightPanel。 |

**工時**：3–4 小時（必須先有 SubViewport）

---

### 候選 3 — tile 溢出 MapArea 視覺裁切

| 軸 | 內容 |
|---|---|
| **方向** | 拖曳到極端 offset 時 tile 不要溢出 MapArea 範圍 |
| **方式** | 任何「真正裁切」都要走 SubViewport（Plan B）— Plan A `MapArea.ClipContents` 對 Node2D 子樹無效；Plan C shader discard 對 81 格不划算 |
| **目標** | 視覺乾淨，極端拖曳不會看到 tile 跑到面板上 |
| **成果** | 與「候選 1 SubViewport 重構」**完全等價** — 不是獨立任務 |
| **風險** | 同候選 1 |

**工時**：併入候選 1

---

## 判讀

| 候選 | 是否該做？ | 觸發條件 |
|---|---|---|
| **SubViewport 重構** | 🟡 **目前不做** | 無 user-visible bug：相鄰 panel 已視覺遮蓋 tile 溢出，正常遊玩看不到 |
| **滑鼠中心 zoom** | 🟢 **不做** | 規格未要求；先做 SubViewport 再說 |
| **tile 溢出裁切** | 🟡 **不獨立做** | 等 SubViewport 觸發 |
| **慣性滑動** | 🔴 **不做** | TRPG 桌遊精度需求不適合 |

**結論**：**目前不採取任何架構級重構**。維持規格書 §3.5 line 1289-1294 的建議行動順序：

1. ✅ Phase 2 — sub-pixel 平滑拖曳（已 ship）
2. ⏸ Phase 3 任務 16（音效 / BGM / UI 動畫）— **若**需要全螢幕 post-processing → 升 SubViewport
3. ⏸ Phase 3 任務 17（存檔讀檔 + 設定選單）— **若**加「畫面縮放 / 字型大小」設定 → 升 SubViewport + Camera State 全套

**不建議現在動**的理由：
- 現在拖曳已平滑，玩家無體感斷裂
- 81 個 Polygon2D tile 60FPS 渲染壓力極小，無效能驅動因素
- 跨 viewport drag-drop 是真實風險，重構成本 > 收益

## 觸發信號（什麼時候應該重新評估）

當以下任一發生時，回頭做候選 1：

- 任務 16 加全螢幕 shader 或 post-processing（如戰鬥場景閃光）
- 任務 17 系統設定加「畫面縮放」或「字型大小」滑桿
- 玩家回饋「拖曳時看到 tile 跑到面板上」（現在被 panel 遮蓋）
- 加入「detail view」放大查看單格內容的需求

## 若要做 SubViewport 升級的執行順序（備案）

預估 4–8 小時。實作時按此順序降低風險：

1. **scenes/main.tscn** — `MapArea` 結構改 `SubViewportContainer + SubViewport + MainMap`
2. **MainMapRenderer / CameraController** — 滑鼠座標全改 `subViewport.GetMousePosition()`
3. **PlayCardZone** — 評估搬進 SubViewport 還是維持原位 + 用 `wrap layer` 跨 viewport
4. **MapArea.resized 訂閱** — 同步 SubViewport.size
5. **小地圖 (Task 10)** — 不需動，因為它讀抽象 `WorldMap.CameraOffset`
6. **回歸測試**：
   - L2: 拖曳手牌 → PlayCardZone 出牌仍可
   - L2: LeftPanel 裝備 ↔ HandDock 拖曳仍可
   - L2: 玩家點擊 tile → ActionTriggerPopup / MoveConfirmDialog 仍可
   - L2: 中鍵拖曳 + sub-pixel 平滑仍生效（不被 SubViewport 縮放破壞）
   - L3: 移動三視角同步（主地圖 / 場景立繪 / 小地圖）
