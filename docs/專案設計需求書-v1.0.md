## 1. 專案概述

### 1.1 遊戲定位
- **類型**：桌遊風格的單人探索型卡牌冒險遊戲，融合 TRPG 骰子判定、角色扮演與地圖探索
- **體驗**：玩家扮演調查員小隊，於限定回合內探索、蒐集線索、面對事件、達成勝利條件
- **視角**：「桌遊放在桌上、玩家俯身觀看」的單點透視，搭配場景立繪三層視差營造臨場感
- **隊伍**：**單人 + NPC 同伴**（主角 1 + AI 同伴 3，共 4 角色色標）；4 角色為預備設計，目前不支援多人輪流

### 1.2 勝負條件

**勝利條件由模組的序幕卡定義**（§3.4.4），透過模組的結局卡（§3.4.5）觸發結局結算。

**勝利條件 vs 失敗條件**：兩者獨立判定，但都受 30 回合上限約束：
- **勝利條件**：完成序幕卡定義的旗標 → 觸發對應結局卡 → 結算為勝利結局
- **失敗條件**（§3.1.6 TurnEnd）：30 回合上限到達 / 重生失敗 / 地圖飽和 → 觸發失敗結局

開發使用的劇情模組「廢棄洋房調查」勝利條件設定為：
- 揭開競斯利洋房的真相
- 救出被困的倖存者
- 在第 30 回合前完成上述旗標

**結局評等**：由結局卡 `endingType` 決定（S/A/B/C 或自訂分類）；貢獻分數（貢獻 × 2 + 裝備填充）僅顯示在 §3.12 統計面板，**不影響評等**。**具體結局內容由模組的結局卡定義**（§3.4.5），可有多張對應不同結局。

**環境效果**：暴風雨等環境設定不會「封路」造成失敗，而是於特定地塊上產生減益（如移動消耗增加或判定減值），詳見 §3.11 持續效果系統。

**特殊結局**：
- **地圖飽和**：MapExpand 階段連續 3 回合無合法可放置區時觸發；對應結局卡由模組定義
- **重生失敗**：HP 歸零時的重生擲骰失敗（§3.10）；對應結局卡由模組定義

- **`core/` 不 reference Godot 命名空間**，可獨立編譯與測試

- 啟動時間 < 5 秒
- Build 體積 < 100 MB

## 3. 核心遊戲機制

### 3.1 回合制架構

- 每局共 N 個大回合（暫定 30 回合，舊版 Core 寫死的 20 回合上限需調整為 30）
- **30 回合上限為失敗條件**，旗標完成（觸發勝利結局卡）為勝利條件；兩者獨立判定，但都受 30 回合上限約束（§1.2）
- 每回合分為五階段：**MapExpand → Draw → Action → EventCheck → TurnEnd**
- 每回合主角 AP 上限 **3**，重置至上限（非累積）
- 每回合主角抽行動卡至手牌上限 **5**
- 同伴每回合持有 **2 AP**，玩家用 AP 時 **50% 機率代消耗**；未用完則自動休息回 HP
- **首回合特例**：玩家角色生成於「初始地塊」，跳過第一回合的 MapExpand 階段直接進入 Draw

#### 3.1.0 遊戲開始與初始地塊

##### 遊戲開始流程
1. 載入模組
2. **顯示序幕卡**（§3.4.4）：全螢幕對話框呈現劇情前提、初始目標
3. 執行序幕卡的 `setupRules`：建立主角、隊伍、初始狀態
4. **放置初始地塊**：依序幕卡 `setupRules.initialTileId` 載入，放於地圖中央 (4, 4)
5. 玩家角色生成於初始地塊
6. 進入回合 1（首回合跳過 MapExpand，直接進入 Draw）

##### 初始地塊規格
- 數量：**1 格**（固定）
- 位置：**地圖中央 (4, 4)**（9×9 網格的正中）
- 內容：由序幕卡 `setupRules.initialTileId` 指定的地塊卡（每個劇情模組需新設計一張作為故事起點）
- 性質：是地塊卡的特例，符合敘事內容（如：洋房入口大廳）

#### 3.1.0a 整局生命週期總覽

```

  └─ 新局 ↓

          ↓
        放置初始地塊於 (4,4)

        進入回合 1
          ↓
┌─── 回合循環（§3.1.1）───────────────────┐
│  MapExpand → Draw → Action →            │

└─────────────────────────────────────────┘
  ↓ 每回合 EventCheck 評估結局卡

#### 3.1.1 回合流程總覽

```
┌──────────────────────────────────────────────┐
│  回合 N 開始                                   │
├──────────────────────────────────────────────┤
│  ① MapExpand   （玩家持地塊卡選放置位置）       │
│      ↓     ※ 首回合跳過                       │
│  ② Draw        （自動，無玩家輸入）            │
│      ↓                                         │

│      ↓                                         │
│  ④ EventCheck  （自動 + 事件選項對話框）       │
│      ↓                                         │
│  ⑤ TurnEnd     （自動，檢查勝負）              │

#### 3.1.2 階段一：MapExpand（地塊鋪設）

| 項目 | 內容 |
|------|------|
| 觸發方式 | 回合開始（首回合除外） |
| 玩家輸入 | 點擊持有的地塊卡 → 點擊可放置區 |
| 結束方式 | 玩家完成放置 |

**執行序列**：
1. 系統從地塊牌堆取出「下一張」地塊作為當前回合放置目標（NEXT 預覽顯示接下來兩張）
2. 該地塊卡進入玩家「持有地塊」狀態，主地圖上**所有合法可放置區**高亮（依放置規則：邊界相鄰未鋪格）
3. 玩家點擊持有地塊 → 卡片進入「待放置」浮動狀態
4. 玩家點擊任一高亮可放置區 → 地塊翻開到 WorldMap 對應 (row, col)
5. 不允許旋轉地塊；地塊卡功能上無方向差別，閱讀面統一朝向玩家
6. 若新地塊有事件：
   - 已揭露事件 → 加入 ORBIT（A 或 B 視條件）
   - 未揭露事件 → 加入 ORBIT C 類
7. NEXT 預覽往前推進一張，從牌堆補一張到第二槽
8. TurnLog 記錄「鋪設地塊：森林 (4,5)」

**無合法可放置區處理**：
- **首次無合法區**（步驟 2 偵測到全圖無合法格）：
  - 跳過本回合 MapExpand，地塊卡放回牌堆頂（下回合優先取出）
  - 訊息氣泡提示「目前無合法可放置區，本回合跳過鋪設」
  - 直接進入 Draw 階段
  - 計數器 `consecutiveNoPlacement += 1`
- **連續 3 回合無合法區**：
  - 觸發**「地圖飽和」特殊結局**（§1.2）
  - 按當前旗標進度與貢獻分數結算 S/A/B/C 評等
- **任何回合成功放置** → 計數器歸零

**對應 Core 服務**：`MapService.ExpandTile()` → `MapService.HasLegalPlacement()` → `EventResolver.RegisterEventToOrbit()` → `EndingService.TriggerSaturationEnding()`（連續 3 回合觸發時）

#### 3.1.3 階段二：Draw（補牌與資源恢復）

| 項目 | 內容 |
|------|------|
| 觸發方式 | MapExpand 結束後自動進入（首回合直接進入） |
| 玩家輸入 | 無 |
| 預期時長 | < 1 秒（含動畫） |

**執行序列**：
1. 主角 AP 重置至上限（**3**）；同伴 AP 補滿（**2 / 角色**）
2. 主角行動卡牌堆抽至手牌上限（**5**）
3. 行動卡抽牌堆若空，重洗棄牌堆
4. 觸發「回合開始」型角色被動技能（例：對最低 HP 同伴 +2 HP）
5. TurnLog 記錄「第 N 回合開始」與被動觸發

**對應 Core 服務**：`TurnLoop.OnDrawPhase()` → `DeckService.DrawToHandLimit()` → `CharacterService.ApplyOnTurnStart()`

#### 3.1.4 階段三：Action（玩家行動）

| 項目 | 內容 |
|------|------|
| 觸發方式 | Draw 結束後自動進入 |
| 玩家輸入 | 自由順序，透過「玩家行動觸發器」浮動視窗 |
| 結束方式 | 點擊「NEXT TURN」按鈕，或 AP 耗盡且無可執行行動 |

**互動入口**：玩家點擊角色所在格 → 彈出「玩家行動觸發器」浮動視窗（§3.9），列出可執行行動。

**可執行行動清單**（行動清單由地塊卡決定，不可使用的行動以亮度調暗顯示）：

| 行動 | AP 消耗 | 觸發方式 |
|------|---------|---------|
| 移動 | **本回合累計第 1 格免費**，第 2 格起每格 1 AP | 觸發器點「移動」 → 滑鼠移到目標 → 預覽路徑 → 確認 |
| 觀察 / 調查 | **本回合首次免費**，之後每次 2 AP | 觸發器點「觀察」 → 依地塊規定擲骰判定 → 成功獲得資源/情報（可揭露 ORBIT C 類事件） |
| 對話 | 1 AP | 觸發器點「對話」（依地塊規定是否有可對話對象決定能否使用） |
| 休息 | 消耗剩餘全部 AP | 觸發器點「休息」 → 每 1 AP 恢復 1 HP |
| 出行動卡 | 卡牌標示 | 拖曳手牌到中央判定區 |
| 釋放主動技能 | 技能標示 | 點擊角色面板技能 |

> 「本回合累計」指該回合內所有移動加總計算（無論分幾次點擊），首格免費僅給最早消耗的那一格；觀察「首次免費」同理為該回合第一次觀察。

**移動預覽流程**（詳見 §5.1.4）：
1. 玩家點觸發器「移動」 → 觸發器隱藏，進入移動模式
2. 滑鼠移到主地圖目標格：只要還有免費移動格數或剩餘 AP，符合距離則顯示**最短路徑**預覽（線條 + AP 消耗）
3. 點擊目標格 → 跳出「確認移動到此地塊？」對話框
4. 確認後執行移動動畫並消耗 AP
5. **右鍵取消**預覽，回到 Action 階段（觸發器重新可呼叫）

**NPC 同伴 AP 與行為**：
- 同伴每回合 **2 AP**（與主角獨立計算）
- **代消耗流程**：玩家每消耗 1 AP 時，依**隊伍同伴順序**逐位檢查：
  1. 該同伴 AP > 0？ → 骰 50% 決定是否代消耗
  2. 命中 → 扣同伴 AP，主角 AP 不扣，流程結束
  3. 未命中 → 檢查下一位同伴
  4. 全部未命中 → 扣主角 AP
  5. 同伴 AP = 0 直接跳過該位，不參與骰
- 同伴 AP 未用完 → 自動以「休息」結算回 HP
- 同伴**跟主角同步移動於同格**（不能獨立移動，也不能移動主角）
- 同伴 AI 自動行為僅限：對話、協助戰鬥、技能釋放

**玩家行動觸發器關閉規則（統一）**：
- 點觸發器中的**任一行動** → 觸發器立即隱藏
- 行動完成後（或玩家中途取消）→ 觸發器重新可呼叫（再點角色所在格）
- 點觸發器以外任何區域 → 觸發器立即關閉

**不可使用提示**：拖曳卡牌到中央但不可使用時，中央浮現紅字「不可使用」，顯示 2 秒後 3 秒淡出，不阻擋點擊。

**對應 Core 服務**：`ActionService.TryExecuteAction()` → `MapService.MoveTo()` / `CardService.PlayCard()` / `NpcAiService.TakeTurn()`

#### 3.1.5 階段四：EventCheck（事件解算）

| 項目 | 內容 |
|------|------|
| 觸發方式 | Action 結束後自動進入 |
| 玩家輸入 | 事件選項對話框 |
| 結束方式 | 所有 A 類槽位處理完畢且無新增 |

**執行序列**：
1. **EventCheck 開頭**：評估所有結局卡 `revealCondition`（§3.4.5），條件滿足則加入 ORBIT C 類；多張同時揭露依結局卡 `priority` 由高至低排序
2. 掃描 ORBIT 軌道 **A 類槽位**（已揭露 + 條件已滿足），依 A→B→C 排列順序處理
3. 對每個 A 事件：
   1. 暫停其他互動，跳出「玩家行動觸發器」浮動視窗，顯示事件文本與選項
   2. 玩家選擇選項（無選項事件 1 秒後自動繼續）
   3. 必要時進行 **2d6 判定**：中央上方判定區顯示骰子動畫（~1 秒）
   4. 結果套用：HP/AP 變化、旗標設定、卡牌獲得/失去、地塊變化等
   5. TurnLog 即時記錄結果
   6. 事件卡進入棄牌堆或移除堆（依事件規則）
   7. **若事件含 `triggerBattle` 效果** → 暫停回合，進入戰鬥子場景（§3.8），結束後**重新評估所有未處理 ORBIT 事件的條件**，再回到 EventCheck 繼續處理 queue
   8. **每處理 1 個 A 後立即重新評估 B 類槽位**（條件可能因 A 事件變化而滿足 → 升級為 A）；同時檢查連鎖深度上限（§3.1.8）
   9. **若觸發到結局卡 A 類** → 直接結束遊戲進入結局結算（§3.12），跳過剩餘 queue
4. 處理 C 類揭露條件（若 A/B 事件觸發了揭露條件 → C 翻面）
5. **EventCheck 結尾**：再次評估所有結局卡 `revealCondition`（捕捉本階段事件副作用造成的揭露）

**事件可能引發的副作用**：
- 地塊卡變化（§3.5、§5.1.5、§8 Phase 2 #11）— EventCheck 中即時變
- 新事件加入 ORBIT（連鎖事件）
- 戰鬥觸發（§3.8 戰鬥子系統）
- 結局卡揭露 / 升 A 觸發（§3.4.5、§3.6.4）

**對應 Core 服務**：`EventResolver.ResolvePending()` → `RollCheckService.PerformCheck()` → `EventEffectService.Apply()` → `BattleService.StartBattle()`（如觸發）→ `EndingService.CheckRevealConditions()`

#### 3.1.6 階段五：TurnEnd（結算與檢核）

| 項目 | 內容 |
|------|------|
| 觸發方式 | EventCheck 結束後自動進入 |
| 玩家輸入 | 無（除非觸發結局對話框） |
| 結束方式 | 進入下回合 MapExpand 或結束遊戲 |

**執行序列**：
1. 檢查**失敗條件**（**勝利條件改由結局卡機制負責**，不在此檢查）：
   - 主角 HP=0 → 觸發**重生擲骰**（§3.10）；若已用過或骰失敗 → 失敗結局
   - 回合數 > 30 → 失敗結局（§3.12）
   - 地圖飽和（連續 3 回合無合法可放置區）→ 「地圖飽和」結局（§1.2）
2. 持續效果結算（裝備被動、buff/debuff、地塊環境效果，詳見 §3.11）
3. 手牌上限檢查（超過則棄至上限）
4. 環境效果推進（依模組定義；暴風雨等於對應地塊上產生減益，詳見 §3.11）
5. 回合數 +1
6. 自動存檔（覆蓋自動存檔槽）
7. 觸發 UI「回合切換」轉場動畫（< 500 ms）
8. 進入下回合 MapExpand

**對應 Core 服務**：`TurnLoop.OnTurnEnd()` → `RespawnService.AttemptRespawn()`（如 HP=0）→ `EndingService.CheckFailureConditions()` → `EffectsService.TickPersistent()` → `SaveService.AutoSave()`

#### 3.1.7 ORBIT 軌道在各階段的狀態變化

| 階段 | 一般事件卡變化 | 結局卡變化 |
|------|-------------|-----------|
| MapExpand | 新地塊事件加入軌道（A/B/C 視狀態） | 不變 |
| Draw | 不變 | 不變 |
| Action | 玩家行動可能滿足 B 條件 → B 升級為 A；可揭露 C | 玩家行動可能滿足結局卡 `revealCondition`（暫存，等 EventCheck 評估） |
| EventCheck | 每處理 1 個 A 後立即重新評估 B；A 觸發後移除；C 依條件翻面 | **開頭**評估所有結局卡 `revealCondition` → 滿足者進 C；**結尾**再評估一次；觸發 A 類結局卡 → 直接結束遊戲（§3.12） |
| TurnEnd | 不變 | 不變 |

#### 3.1.8 異常與特殊流程

| 情境 | 處理方式 |
|------|---------|
| 首回合 | 跳過 MapExpand，玩家角色生成於初始地塊 → 直接 Draw |
| EventCheck 中觸發新事件（連鎖） | 加入處理 queue 末端，依序處理；**深度上限 5 層 + 同事件 ID 在同一 EventCheck 中只觸發 1 次**；超出層數的事件**移至下回合 ORBIT 軌道最前端**，與新事件合併後依 A→B→C 順序處理 |
| ORBIT 同階段多張 A | 依 A→B→C 排列順序執行 |
| 戰鬥觸發 | 暫停回合流程，進入戰鬥子場景（§3.8），結束後重新評估所有未處理 ORBIT 事件條件，再回到原階段（**不消耗回合數**） |
| 玩家中途存檔 | 僅可在 Action 階段觸發；其他階段排隊至下一 Action |
| 玩家中途讀檔 | 主選單可進入；遊戲中僅可在 Action 階段觸發；其他階段排隊至下一 Action（詳見 §7.4） |
| Action 階段 AP 用盡且無可執行行動 | 顯示提示 + 自動結束 Action 進入 EventCheck |
| EventCheck 處理時間過長 | 提供「跳過動畫」按鈕加速 |
| MapExpand 無合法可放置區 | **首次**：跳過本回合 MapExpand，地塊卡放回牌堆頂（詳見 §3.1.2）；**連續 3 回合**：觸發「地圖飽和」特殊結局（§1.2） |
| 主角 HP 歸零（戰鬥內外皆然） | 觸發**重生擲骰**（§3.10）；一局僅 1 次；失敗或已用過則進失敗結局（§3.12） |

#### 3.1.9 Core 服務對應總覽

```
GameLifecycle （遊戲生命週期主控）
    ├─ PrologueService    → 載入並顯示序幕卡，執行 setupRules（§3.4.4）
    ├─ TurnLoop           → 5 階段（MapExpand/Draw/Action/EventCheck/TurnEnd）
    │   ├─ MapExpand    → MapService, EventResolver
    │   ├─ DrawPhase    → DeckService, CharacterService
    │   ├─ ActionPhase  → ActionService, MapService, CardService, NpcAiService, EffectsService
    │   ├─ EventCheck   → EventResolver, RollCheckService, EventEffectService, BattleService, EndingService.CheckRevealConditions
    │   └─ TurnEnd      → RespawnService, EndingService.CheckFailureConditions, EffectsService.TickPersistent, SaveService
    └─ EndingService      → 結局卡評估 / 結局結算 / 統計面板 / 回主選單（§3.12）
```

每階段切換時透過 Godot Signal `phase_changed(PhaseType)` 通知 UI 層更新對應顯示（如 TopBar 階段標示、可互動元素 enable/disable）。

整局生命週期切換（序幕 → 回合循環 → 結局）由 `GameLifecycle` 主控發出 `lifecycle_changed(LifecyclePhase)` 訊號。

#### 3.1.10 待釐清事項彙整

✅ 所有先前列出的待釐清事項皆已釐清：
- AP 累積 → **每回合重置至上限 3**（§3.1）
- 手牌上限 → **5**（§3.1）
- 同伴 AP 是否獨立 → **獨立，每回合 2 AP**（§3.1.4）
- 連鎖事件深度限制 → **5 層 + 同事件去重**（§3.1.8）
- 戰鬥子場景是否消耗回合數 → **不消耗**（§3.8.7）
- MapExpand 無合法可放置區 → **首次跳過，連續 3 回合觸發「地圖飽和」結局**（§3.1.2、§1.2）
- 地塊放置距離限制 → **4 方向相鄰未鋪格**（§3.5.2）
- 條件 DSL 文法 → **採用 JsonLogic**（§7.3）

### 3.2 角色系統

#### 3.2.1 隊伍組成
- 主角 1（必備）+ NPC 同伴 1~3（彈性）

#### 3.2.2 主角屬性
| 屬性 | 用途 |
|------|------|
| HP（生命） | 歸零失敗 / 退回初始地塊 |
| AP（行動點） | 上限 3，每回合重置；用於行動消耗（§3.1.4） |
| 紅戰鬥 / 綠探索 / 藍社交 / 紫知識 | 2d6 判定加值 |

#### 3.2.3 主角技能
- 配置：**1 主動 + 1~3 被動**（依角色重要性決定數量）
- 範例：
  - 主動：消耗手牌獲得 HP 回復
  - 被動：回合開始為最低 HP 同伴補 2 HP
  - 被動：進入重要地塊給予線索碎片

#### 3.2.4 NPC 同伴屬性
- **無 4 屬性**（同伴主要功能為敘事協助與戰鬥輔助，不參與判定）
- 擁有：HP、AP（每回合 2，主回合 §3.1.4 / 戰鬥內 §3.8.6）
- 擁有同伴專屬技能：影響主角（如「為最低 HP 同伴補 2 HP」）、戰鬥輔助（§3.8.12）
- 移動：跟隨主角同步移動於同格（§3.7）
- 戰鬥內無法執行 Basic 5 種行動，僅能執行戰鬥輔助（§3.8.12）

### 3.3 判定系統（2d6）
- **公式**：`骰點 + 主角對應屬性 + 地塊修正 vs 對應屬性目標值（屬性TN）`
- **判定者**：玩家僅能操作主角，所有判定使用主角屬性
- **結果分級**：
  - **戰鬥中**：分為大失敗 / 失敗 / 成功 / 大成功（提供額外傷害或減益）
  - **其餘判定**：預設只有成功 / 失敗
  - 卡牌可規定特殊分級規則（保留擴充空間）
- 雙 6 / 雙 1 觸發奇蹟機制（暫定）
- 所有判定記錄於 Turn Log

### 3.4 卡牌系統

#### 3.4.1 卡牌類型與流轉規則

| 類型 | 來源 | 牌庫管理 | 流轉去向 |
|------|------|---------|---------|
| **序幕卡** | 模組必備（每模組 1 張） | 遊戲開始時一次性顯示 | 不進入任何流轉，僅作為遊戲開場與規則定義（§3.4.4） |
| **行動卡** | 主角手牌 | 抽牌堆 / 棄牌堆 / 移除堆 | 出牌後進棄牌堆；特殊效果可移除 |
| **事件卡** | 地塊或回合觸發 | 進入 ORBIT 軌道（§3.6） | 觸發後進棄牌堆或移除堆，依事件規則 |
| **裝備卡** | 事件卡 / 戰鬥卡結算獲得 | **無牌庫** | 獲得時即放置在合法裝備格；無合法格則棄置 |
| **地塊卡** | 地塊牌堆 | **無牌庫流轉**（依序觸發放置） | 放置後成為 WorldMap 一格，不回收 |
| **戰鬥卡** | 事件卡的 `triggerBattle` 效果帶出 | **無牌庫**（依事件即時生成） | 戰鬥結束後丟棄；勝利時結算 LootEffects |
| **結局卡** | 模組多張，揭露條件滿足才現身 | 揭露後進入 ORBIT 軌道 C 類槽位（§3.4.5、§3.6） | 觸發後**直接結束遊戲**，進入結局結算；只觸發一次 |

#### 3.4.2 牌庫管理細節
- **僅行動卡**有完整的「抽 / 棄 / 移除」三堆機制
- 事件卡的「牌庫」實作為 ORBIT 軌道**第 8 位置展開鈕**（§3.6）：點擊展開所有未觸發事件清單
- 地塊卡為線性序列，依抽取順序逐張放置
- 裝備卡與戰鬥卡為「即時生成 + 即時消耗」型卡牌

#### 3.4.3 裝備卡與 3×3 裝備格

**裝備格槽位類型**（3×3 = 9 格）：

| 位置 | 槽位 | 用途 |
|------|------|------|
| 上 | 頭部裝備 | 頭盔、帽子等 |
| 上 | 主手（武器） | 主要攻擊裝備 |
| 上 | 副手（武器或防具） | 雙武器流派或盾牌 |
| 中 | 身體裝備 | 護甲、長袍等 |
| 中 | 飾品 | 戒指、項鍊 |
| 中 | 飾品 | 同上 |
| 下 | 足部裝備 | 靴子、鞋類 |
| 下 | **口袋**（消耗品） | 行動或戰鬥階段可使用的 1 次性消耗品 |
| 下 | **背包** | 最多額外收納 **3 張裝備卡** |

**裝備卡規則**：
- 一張裝備卡**可適用多種槽位**（例：護身符可放任一飾品格）
- 所有裝備卡**皆可放入背包**
- **背包中的裝備不計算效果**，僅作為儲存
- **獲得新裝備時自動入背包**（不直接生效）
- 玩家在 **Action 階段任何時候可開背包整理**（不需事件特別允許）
- 整理動作：將背包裝備拖曳到合法槽位即可生效；可雙向交換
- **戰鬥中限制**：戰鬥內**僅可使用口袋槽位的消耗品**；其他槽位裝備換裝**禁用**（必須回主回合 Action 階段才能整理背包與換裝）

#### 3.4.4 序幕卡

##### 用途
定義本場遊戲的**劇情前提**、**勝敗條件**與**設置條件**。每個劇情模組必備 1 張。

##### 顯示時機
- **遊戲開始時**（首回合 MapExpand 之前）以全螢幕對話框顯示
- 玩家點擊「開始遊戲」後關閉，進入回合 1 流程
- 之後可從系統選項（§4.1 #6）內隨時重新查看

##### 內容規格
| 欄位 | 用途 |
|------|------|
| `prologueText` | 劇情開場敘述（可分多頁） |
| `initialGoals` | 初始目標清單，用於前期導引玩家（**目標可隨劇情變換**，僅作為初期導引） |
| `victoryConditions` | 勝利旗標清單（取代 §1.2 寫死的 3 條，由模組定義） |
| `failureConditions` | 失敗條件清單 |
| `setupRules` | 起始設置：主角屬性 / HP / AP、隊伍同伴名單、初始地塊 ID、初始行動卡牌堆、初始手牌大小、初始裝備、重生擲骰規則 |
| `art` | 序幕卡插圖 |

**`setupRules` 子欄位**：
- `hero`：主角屬性與 HP/AP 起始值
- `companions`：NPC 同伴 ID 清單（對應 `npc_companion.json`）
- `initialTileId`：初始地塊卡 ID（將放於地圖中央 4,4）
- `initialActionDeck`：行動卡 ID 清單（首回合 Draw 由此抽卡）
- `initialHandSize`：手牌上限（預設 5）
- `initialEquipment`：起始裝備 ID 清單（自動入背包，可預設裝在合法槽位）
- `respawnRoll`：重生擲骰規則（§3.10），含 `tn`（目標值）等

##### 範例
```json
{
  "id": "abandoned-mansion-prologue",
  "prologueText": [
    "一封來自瀕死管家的信，將你引向廢棄的競斯利洋房...",
    "傳聞洋房裡仍有倖存者被困，而暴風雨即將封路。"
  ],
  "initialGoals": [
    "進入洋房探索線索",
    "尋找並救出倖存者",
    "在暴風雨完全封路前離開"
  ],
  "victoryConditions": [
    {"flagSet": "truth_revealed"},
    {"flagSet": "survivor_rescued"},
    {"flagSet": "escaped_before_storm"}
  ],
  "failureConditions": [
    {"heroHpZero": true},
    {"turnAtLeast": 30}
  ],
  "setupRules": {
    "hero": {"hp": 10, "ap": 3, "attr": {"combat": 2, "exploration": 3, "social": 1, "knowledge": 2}},
    "companions": ["esther", "dominic"],
    "initialTileId": "manor-entrance",
    "initialActionDeck": ["card-investigate", "card-investigate", "card-quick-step", "card-parley", "card-focus", "card-aid"],
    "initialHandSize": 5,
    "initialEquipment": ["worn-coat"],
    "respawnRoll": {"tn": 7}

```

##### 對應流程
- §3.1 流程開始前，先載入序幕卡並執行 `setupRules`
- §3.1.0 初始地塊改為「由序幕卡 `setupRules.initialTileId` 指定」
- §1.2 勝利條件改為「由模組序幕卡的 `victoryConditions` 定義」

#### 3.4.5 結局卡

##### 用途
定義模組可能的多種結局；類似事件卡有揭露/觸發條件，但觸發後**直接結束遊戲**進入結局結算。

##### 與事件卡的差異
| 面向 | 事件卡 | 結局卡 |
|------|--------|--------|
| 揭露條件 | JsonLogic | JsonLogic（同） |
| 觸發條件 | JsonLogic | JsonLogic（同） |
| 觸發後 | 進棄牌堆 / 移除堆，遊戲繼續 | **直接結束遊戲**，進入結局結算 |
| 觸發次數 | 可多次（依事件規則） | **只觸發 1 次**（一旦觸發即遊戲結束） |
| 進入軌道 | 揭露後進 C → 條件滿足升 A | 揭露後進 C → 條件滿足升 A → EventCheck 觸發即結局 |

##### 流程
1. 模組可定義多張結局卡（如：完美結局、好結局、壞結局、特定條件結局）
2. 每張結局卡有自己的 `revealCondition` 與 `triggerCondition`
3. **平時隱藏**，揭露條件滿足才進入 ORBIT 軌道 C 類槽位
4. **`triggerCondition` 評估時機**：與一般事件 B 共用機制（§3.1.5：每處理 1 個 A 後重新評估所有 B 與結局卡 C 的 triggerCondition）
5. EventCheck 階段檢查到 A 類結局卡 → 觸發結局結算
6. 結局結算：顯示結局敘述 + 評等（依 `endingType`）+ 統計面板 → 回主選單
7. **多張結局卡互斥**：任一觸發即遊戲結束，其他結局卡作廢

##### 內容規格
| 欄位 | 用途 |
|------|------|
| `id` | 結局唯一 ID |
| `endingType` | 評等：`S` / `A` / `B` / `C` 或自訂分類 |
| `priority` | 整數，越大越優先；多張結局卡同時揭露時依此排序（同 priority 依模組載入順序） |
| `endingText` | 結局敘述（可分多頁） |
| `revealCondition` | JsonLogic 揭露條件（如：持有特定道具、特定事件成敗、移到特定地塊） |
| `triggerCondition` | JsonLogic 觸發條件（揭露後仍需滿足才觸發） |
| `scoreCalculation` | 分數計算覆寫（可選；不填則用預設公式 §1.2） |
| `art` | 結局卡插圖 |

##### 範例
```json
{
  "id": "ending-perfect",
  "endingType": "S",
  "priority": 100,
  "endingText": [
    "晨曦穿過洋房的破窗，你帶著倖存者與真相走出大門...",
    "暴風雨剛剛停歇，新的一天即將開始。"
  ],
  "revealCondition": {
    "and": [
      {"==": [{"var": "flag.truth_revealed"}, true]},
      {"==": [{"var": "flag.survivor_rescued"}, true]}
    ]
  },
  "triggerCondition": {
    "and": [
      {"==": [{"var": "currentTile.tileCardId"}, "manor-entrance"]},
      {"==": [{"var": "flag.escaped_before_storm"}, true]}
    ]
  },
  "art": "ending-perfect.png"
}
```

### 3.5 地圖系統

#### 3.5.1 基本架構
- **資料層**：9×9 全圖網格（`WorldMap`）
- **視野層**：玩家為中心 5×5 可見區
- **渲染層**：單點透視（消失點往畫面上方收縮），呈現「桌遊放在桌上」視角
- **地塊資料**：地形、探索狀態、事件旗標、判定修正、可通行性、變化規則
- 詳見 §5.1

#### 3.5.2 地塊放置與移動規則
- 在 MapExpand 階段執行（§3.1.2）
- 玩家持有當前回合的地塊卡 → 點擊任一**合法可放置區**
- 合法區規則：必須與已放置地塊相鄰（**4 方向**，不含對角線），且該格未被佔用
- **不允許旋轉地塊**；地塊功能上無方向差別，閱讀面統一朝向玩家
- 移動同樣為 **4 方向**（B3.1）
- **地塊事件僅在「停留」時觸發**，經過不會（B3.4）

#### 3.5.3 地塊卡變化功能
- 部分地塊可因事件觸發而變成另一張地塊卡（例：森林被火災事件變成焦土）
- 變化由事件卡的 `transformTile` 效果觸發，於 EventCheck 階段即時變化
- 變化規則於 `tile.json` schema 中以 `transformations` 欄位定義
- 變化條件採 **JsonLogic** 條件 DSL（§7.3）撰寫
- 變化會更新 `TileData` 的 `Terrain`、視覺、事件旗標，但保留 (row, col) 位置與探索狀態

範例（森林被火災變焦土）：
```json
{
  "triggerEventId": "fire-spreads",
  "transformsTo": "scorched-earth",
  "condition": {
    "and": [
      {"==": [{"var": "currentTile.terrain"}, "forest"]},
      {"==": [{"var": "flag.fire_started"}, true]}
    ]
  }
}
```

### 3.6 事件 / ORBIT 軌道系統

#### 3.6.1 軌道結構
- **顯示 7 個槽位**，依 **A → B → C** 順序排列（A 在最左）：
  - **A 類**：已揭露 + 條件已滿足（亮色，本回合 EventCheck 可觸發）
  - **B 類**：已揭露 + 條件未滿足（灰色，不可觸發）
  - **C 類**：未揭露（背面朝上，被玩家行動或其他事件揭露時翻面）
- **第 8 位置為「點擊展開全部」按鈕**（非槽位）：
  - 當待處理事件數量超過 7 時，第 8 位置顯示為展開圖示
  - 點擊後跳出全部未觸發事件清單（可滾動）
  - 等同事件卡的「牌庫」入口
- 槽位分配**浮動**：A/B/C 類各佔幾槽不固定，依當前事件數量動態排列

#### 3.6.2 揭露條件
- C 類事件揭露條件可為：玩家進入特定地塊、執行特定行動（如**透過觀察行動，依地塊卡規定可能揭露**）、其他事件結算副作用
- 揭露後依條件判定升 A 或留 B
- 玩家**無法**「免費主動翻面」C 類事件，必須透過合法行動觸發揭露
- A/B/C 類別判定的條件採 **JsonLogic** 條件 DSL（§7.3）

範例（事件揭露條件：主角探索 ≥ 4 且回合 ≥ 5）：
```json
{
  "revealCondition": {
    "and": [
      {">=": [{"var": "hero.attr.exploration"}, 4]},
      {">=": [{"var": "turn"}, 5]}
    ]
  }
}
```

#### 3.6.3 對應流程
- 詳見 §3.1.5 EventCheck 階段
- ORBIT 槽位為視覺呈現，底層為事件 queue + condition state

#### 3.6.4 結局卡在 ORBIT 中的特殊行為
- 結局卡（§3.4.5）平時**隱藏**，不佔用 ORBIT 槽位
- **revealCondition 評估時機**：每回合 EventCheck 階段的**開頭與結尾各評估一次**所有結局卡的揭露條件
- 多張結局卡同時揭露 → 依 `priority` 由高至低排序進入 ORBIT C 類；同 priority 依模組載入順序
- 揭露條件滿足時 → 進入 ORBIT 軌道 C 類槽位（與一般事件卡一樣占位）
- **triggerCondition 評估時機**：與一般 B 共用機制（§3.1.5：每處理 1 個 A 後重新評估所有 B 與結局卡 C 的 triggerCondition）
- 觸發條件滿足時 → 升級為 A 類
- EventCheck 階段觸發 A 類結局卡 → **直接結束遊戲**進入結局結算（§3.12，不再處理後續 ORBIT 事件）
- 結局卡的卡背樣式有別於一般事件卡（建議金色邊框 + 特殊符號），讓玩家知道「重要事件即將發生」

### 3.7 同伴 AI
- 沿用舊版 NPC AI 服務
- **移動規則**：
  - 同伴**跟隨主角同步移動於同格**
  - **不可獨立移動，亦不可移動主角**
  - 卡關（無法跟隨）時：**綁定主角位置**（強制傳送至主角格）
- **自動行動**：對話、協助戰鬥（§3.8.7）、技能釋放
- **AP 機制**：每回合 2 AP，與主角 AP 獨立計算（詳見 §3.1.4）
- 同伴態度系統（暫定，舊版凍結，未排入本次開發範圍）

### 3.8 戰鬥子系統

#### 3.8.1 戰鬥觸發
- 由事件卡的 `triggerBattle` 效果帶出戰鬥卡
- 戰鬥開始時暫停回合流程，進入獨立戰鬥子場景
- 戰鬥結束後回到原回合階段繼續處理

#### 3.8.2 戰鬥卡資料結構（對應 Core `BattleCard`）

```
[戰鬥卡：書房鬼魂]
─────────────────────────────────────
敵人名稱：書房鬼魂
外觀描述：……
─────────────────────────────────────
數值（EnemyStats）：
  HP            : 20
  AttackPower   : 4   ← 敵方攻擊基準傷害 + 玩家命中 TN
  Evasion       : 8   ← 玩家攻擊的固定 TN
  Defense       : 2   ← 玩家命中時的傷害減免
  Weakness      : "ritual"  ⚠️ 欄位解析完成、傷害計算未用

EncounterTn   : 9    ← 遭遇檢定 TN（玩家以 2d6 + Skill + 加值 判定）

EnemyActions  : 多筆，每回合挑選一筆執行
  ┌───────────────────────────────────────────────────┐
  │ id           kind     targeting    trigger              weight  payload      │
  ├───────────────────────────────────────────────────┤
  │ basic-slash  Attack   LowestHp     always               3       damage:0     │
  │ prep-slam    Prepare  LowestHp     hpAtMost{0.7}        2       —            │
  │ coffin-burst Attack   LowestHp     preparedLastTurn     5       damage:2     │
  │ vanish       Flee     LowestHp     hpAtMost{0.2}        1       —            │
  └───────────────────────────────────────────────────┘

LootEffects   : 勝利戰利品
  - grantEquipment { id: "torn-journal" }
  - setFlag        { key: "study_wraith_banished", value: true }
─────────────────────────────────────
```

#### 3.8.3 EnemyAction 觸發器（`EnemyActionTrigger`）

| 觸發器 | 條件說明 |
|--------|---------|
| `always` | 任何時候皆可觸發 |
| `hpAtMost{ratio}` | 敵方 HP 比例 ≤ ratio 時觸發 |
| `playerHpAtMost{ratio}` | 玩家 HP 比例 ≤ ratio 時觸發 |
| `roundAtLeast{round}` | 戰鬥達到第 round 回合以上 |
| `preparedLastTurn` | 上回合執行了 Prepare |

**選擇規則**：
1. 多筆符合時，依 Priority 排序：`preparedLastTurn > hpAtMost > playerHpAtMost > roundAtLeast > always`
2. 取最高優先級組
3. 同優先級依 `weight` 加權抽籤

#### 3.8.4 TargetingRule

| 規則 | 行為 |
|------|------|
| `LowestHp` | 鎖定當前 HP 最低的玩家方角色 |
| `HighestHp` | 鎖定當前 HP 最高的玩家方角色（原舊版 `HighestPower`，因玩家方無 Power 屬性，以 HP 代理；待未來補真正 Power 屬性後升級） |
| `Random` | 隨機選一名 |

**反鎖定機制**：連續 2 回合鎖定同一玩家後，第 3 回合強制隨機攻擊其他目標。

#### 3.8.5 EnemyActionKind

| 種類 | 效果 |
|------|------|
| `Attack` | 對目標造成傷害（payload.damage + AttackPower） |
| `UseItem` | 傷害 + 附加狀態效果 |
| `Prepare` | 進入準備姿態，下次攻擊傷害 ×2 |
| `Defend` | 進入防禦姿態，下次受擊傷害減半 |
| `Flee` | 結束戰鬥，結算為 `EnemyFled`（不掉落 LootEffects） |

#### 3.8.6 戰鬥內 AP

戰鬥內 AP 與主回合 AP **獨立計算**，戰鬥結束後不影響主回合 AP。

| 項目 | 規則 |
|------|------|
| 主角 AP 上限 | **3**（與主回合一致） |
| 補滿時機 | 每戰鬥回合 PlayerTurn 開始時補滿至上限 |
| 同伴 AP 上限 | **2**（與主回合一致） |
| Ambushed 修正 | Phase A 遭遇結果為 Ambushed → 戰鬥首回合主角 AP −1（最終 AP=2） |

**消耗來源**：
- **反應動作**：`Dodge` / `Block` 各 1 AP（§3.8.10 Phase C 玩家反應）
- **Basic 行動**：`Attack` / `Defend` / `Observe` / `Reposition` / `Retreat` 不消耗 AP
- **ActionCard 行動**：依卡牌標示
- **同伴行動**：消耗同伴自己的 AP

#### 3.8.7 Reveal 機制（資訊揭露）

由 Phase A 遭遇擲骰結果決定，**戰鬥中不會升級**：

| 等級 | 揭露內容 | UI 呈現 |
|------|---------|--------|
| **Full** | HP 數值 / 所有 EnemyAction 名稱與簡述 / Weakness / LootEffects 預覽 | 完整資訊面板 |
| **Partial** | HP 數值 / **已使用過的** EnemyAction（戰鬥中累積揭露）/ Weakness | 半透明資訊；未揭露的標 `???` |
| **None** | 僅敵人外觀；HP 改為粗略條（高/中/低 3 段） | 大部分標 `???`；每次敵方使用 EnemyAction 時即時加入已知清單 |

**通用規則**：
- EnemyAction 的觸發條件（trigger / weight）**任何等級都不揭露**（避免破壞戰術深度）
- LootEffects 僅 Full 預覽
- **Reveal 等級不變**（只在 Encounter 一次決定，戰鬥中不升級）
- **但 None / Partial 的 EnemyAction 已知清單會隨戰鬥推進累積**：
  - 被使用過的 EnemyAction 自動加入已知清單
  - Basic `Observe` 動作每次揭露 1 個未知 EnemyAction
  - 已知清單只增不減

#### 3.8.8 戰鬥流程：Phase A — Encounter（遭遇）

> **術語定義**：
> - **PlayerTurn（玩家方輪）** = 玩家方一輪行動 + 同伴輔助子階段（Phase B 完整流程）
> - **EnemyTurn（敵方輪）** = 敵方執行 1 次 EnemyAction（Phase C 開頭）
> - **戰鬥回合** = 1 次 PlayerTurn + 1 次 EnemyTurn（含 AwaitingResponse）

`BattleEngine.Start(card)` 建立 `BattleState`，隨即執行一次 `ResolveEncounter`：

```
若戰鬥卡未預先指定結果，則進行遭遇擲骰：

遭遇擲骰 = 2d6 + Skill（綠探索屬性）+ Feet 裝備 SkillBonus
↓ 與 card.EncounterTn 比對：

  double6                  → 強制 Advantage（覆蓋 TN 比較）
  total ≥ TN+3             → Advantage：Reveal=Full、玩家先攻
  total ≥ TN（且非 double1）→ Normal：   Reveal=Partial、玩家先攻
  否則                      → Ambushed：Reveal=None、敵方先攻、首回合主角 AP −1
  double1                  → 額外標記 vulnerable（§3.8.12 / §3.11）
```

**一次擲骰同時決定**：資訊揭露量、先攻、是否被奇襲、是否帶 vulnerable

#### 3.8.9 戰鬥流程：Phase B — PlayerTurn（玩家回合）

PlayerTurn 開始時補 AP 至上限，玩家依 AP 與行動規則執行行動，行動結束後進 §3.8.12 同伴輔助子階段，再進 Phase C。

> **每戰鬥回合可執行多個行動**，僅受 AP 與各源次數上限限制；行動順序由玩家自定。
> 例：可同回合「Basic Attack（無 AP）+ 出 1 張 ActionCard 攻擊（消耗 AP）+ 用 1 個 Character ability + Reposition」直到 AP 用盡或主動結束 PlayerTurn。
> 攻擊型 ActionCard 與 Basic Attack **互不干擾**（各自次數獨立計算）。

##### 三種行動源

| 行動源 | 子類 / 擲骰 | 規則 |
|--------|------------|------|
| **Basic**（`BasicActionChoice`）| `Attack` / `Defend` / `Observe` / `Reposition` / `Retreat` | **每種** Basic 動作每戰鬥回合限用 1 次；無資源成本（`Attack` 仍擲骰）；`Dodge` / `Block` 為反應動作（§3.8.10） |
| **Character**（`CharacterActionChoice`）| 角色 `combatAbilities` 的每戰冷卻技能；附 `RollBonus` 或 `DamageMultiplier` | **每戰僅可使用 1 次**（用 `BattleState.usedCombatAbilities` 追蹤） |
| **ActionCard**（`CardActionChoice`）| 手牌任一張含 `combat` 欄位的卡；依 `route = RollBonus` 或 `DamageMultiplier` 參與擲骰 | 消耗 AP，使用後**進入棄牌堆**（無冷卻機制） |

##### Basic 動作詳述

| 動作 | AP | 效果 |
|------|----|------|
| `Attack` | 0 | 進行攻擊擲骰（公式見下） |
| `Defend` | 0 | 本戰鬥回合 Dodge 加值 +2（單回合不累積，玩家方輪結束清零） |
| `Observe` | 0 | 揭露敵方 1 個未知 EnemyAction（僅在 Reveal=None/Partial 時有意義） |
| `Reposition` | 0 | 累積 Dodge 加值 +1（戰鬥內可累積，**最多 +3**，戰鬥結束清零） |
| `Retreat` | 0 | 結束戰鬥（結果為 EnemyFled，無戰利品） |

##### 攻擊擲骰公式（`RollAttack`）

```
擲骰總分 = 2d6 + Power（紅戰鬥屬性）+ WeaponHitBonus + RollBonus（來源加值）
↓ 比對敵方 Evasion（固定）：

  double6              → CritSuccess：必定命中，傷害 +3
  total ≥ Evasion      → Success：傷害 = max(1, WeaponDamage + Power − Defense) × DamageMultiplier
  total ≥ Evasion − 2  → Partial：傷害 = max(1, floor(Success 傷害 / 2))
  total <  Evasion − 2 → Fail：無傷
  double1              → CritFail：未命中 + 標記 vulnerable
```

##### DamageMultiplier 規則
- Basic Attack 預設 ×1
- Character / Card 未指定 `damageMultiplier` → 視為 ×1
- 多重來源**連乘**，**上限 ×5.0**

#### 3.8.10 戰鬥流程：Phase C — EnemyTurn & AwaitingResponse（敵方回合與反應）

##### EnemyTurn 流程
1. `PlanEnemyAction` 依 `EnemyAction[]` 的觸發器 Priority + Weight 抽選動作（§3.8.3）
2. 需要目標時以 `TargetingRule` 選定（§3.8.4，連續 2 回合鎖同一目標 → 第 3 回合強制隨機）
3. 動作分流：
   - `Attack` / `UseItem` → 進入 AwaitingResponse（玩家反應）
   - `Prepare` → 蓄勢，下次攻擊傷害 ×2（標記 `EnemyPrepared`）
   - `Defend` → 進入防禦姿態，下次受擊傷害減半
   - `Flee` → 直接結束戰鬥（`EnemyFled`，無戰利品）

##### Atk 計算
```
Atk = card.Stats.AttackPower + action.Payload.Damage
若敵方 EnemyPrepared → Atk × 2
```
> 玩家 vulnerable 狀態的 +2 傷害**不計入 Atk**，而是依 §3.11 vulnerable 規則套用為 `incomingDamage` +2（最終結算時加總，避免規則散落）。

##### 同伴抵擋傷害（優先檢查）
進入 AwaitingResponse **之前**，依隊伍順序檢查同伴是否有「待命抵擋」蓄勢效果（§3.8.12）：
- **有** → 該同伴代受全額傷害（玩家不需反應，效果消除）；蓄勢時已扣 1 AP，**觸發時不再扣**
- **無** → 玩家從 3 種反應擇一

##### 玩家 3 種反應

| 反應 | AP | 擲骰 | 結果 |
|------|----|------|------|
| `Accept` | 0 | 無 | 全額受傷；受傷後**手牌+1**（若手牌已達上限 5 → **不抽**） |
| `Dodge` | 1 | 2d6 + Skill（綠探索）+ RepositionStack + DefendBonus(本回合) | 詳見下方分級 |
| `Block` | 1 | 2d6 + Power（紅戰鬥）+ ShieldHitBonus | 詳見下方分級（重心在 Power/Shield）；**需副手裝備為盾**，否則此選項禁用（亮度調暗） |

##### Dodge / Block 分級
```
double6        → 必定無傷
total ≥ Atk+2  → 無傷
total ≥ Atk    → 半傷（max(1, floor(Atk / 2))）
total <  Atk   → 全傷
double1        → 必定全傷 + 標記 vulnerable
```

#### 3.8.11 戰鬥流程：Phase D — End（結束）

| 條件 | 結果 | 附帶處理 |
|------|------|---------|
| 敵方 HP=0 | `Victory` | 套用 `card.LootEffects` |
| 玩家選 `Retreat` 或敵方 `Flee` | `EnemyFled` | 無戰利品 |
| **主角 HP=0** | 進入 §3.10 重生擲骰 | 成功 → 戰鬥中斷退回初始地塊（敵人脫戰，無戰利品；**該戰鬥卡視為未完成**，下次由事件再次帶出時 HP/狀態完全重置）；失敗或已用過 → `Defeat` 進失敗結局 |
| 同伴 HP=0 | 該場戰鬥退場 | 戰鬥結束以 1 HP 回歸隊伍 |

戰鬥結束後**重新評估所有未處理 ORBIT 事件條件**（§3.1.5），再回到觸發戰鬥的事件後續處理。戰鬥**不消耗**主回合的回合數計數。

**對應 Core 服務**：`BattleService.StartBattle()` → `BattleEngine.RunBattleLoop()` → `EnemyActionSelector.PickAction()` → `RespawnService.AttemptRespawn()`（如主角 HP=0）

#### 3.8.12 同伴戰鬥行為（按需介入）

##### AP 與基本規則
- 同伴每戰鬥回合 **2 AP**（與主回合一致）
- 同伴 HP=0 → 該場退場（§3.8.11），戰鬥結束以 1 HP 回歸
- 同伴**不能使用 Basic 5 種行動**（同伴無屬性 §3.2.4）
- 同伴 AP 用不完不會自動回 HP（與主回合 §3.1.4 不同；戰鬥內以 Loot 與事件回復為主）

##### 兩種 AP 用途

**1. 主動輔助**（Phase B 末，主角行動結束後）：
依隊伍順序，每位存活同伴**自動**執行 1 次輔助技（**輔助類型由 `npc_companion.json` 固定設定**，戰鬥中自動觸發；玩家無法干預，保持戰術簡潔）：
- **攻擊加乘**：主角下次攻擊傷害 +2（消耗 1 AP）
- **行動輔助**：主角下次任一擲骰（攻擊 / Dodge / Block / 戰鬥外判定）+1~+2（消耗 1 AP）；玩家可自行決定何時套用（消耗該蓄勢效果）
- **抵擋傷害（蓄勢）**：標記為「待命抵擋」，下次主角受擊時自動觸發（消耗 1 AP）

**2. 即時抵擋**（Phase C 主角被擊時）：
進入 AwaitingResponse 之前，依隊伍順序檢查同伴是否有「待命抵擋」蓄勢效果：
- 有 → 該同伴代受全額傷害（效果消除，**蓄勢時已扣 1 AP，觸發時不再扣**）
- 無 → 玩家從 3 種反應擇一

##### Vulnerable 狀態
詳見 §3.11 持續效果系統。同伴受擊時也適用 vulnerable 標記。

### 3.9 訊息氣泡系統

#### 3.9.1 用途
位於畫面中央上方（NEXT TURN 按鈕附近），用於提示**當前回合需要關注的事件、對話、待處理事項**。取代原構想的「4 角色色標頭像」（已確認不存在）。

#### 3.9.2 顯示內容
- 當前回合要觸發的事件提示（例：「ORBIT A1：書房鬼魂 將於 EventCheck 觸發」）
- NPC 同伴的對話氣泡（例：「同伴說：這扇門看起來有古怪…」）
- 系統提示（例：「AP 即將不足，建議結束回合」）
- 待處理事項清單（例：「2 個事件待解算 / 1 個地塊待放置」）

#### 3.9.3 互動規格
- **顯示時機**：MapExpand / Action / EventCheck 階段
- **預設**：氣泡為摺疊圖示（小圓點），**不會自動展開**
- **點擊**：玩家手動點擊圖示後展開該則訊息；展開後點氣泡內可跳轉到對應的 ORBIT 槽位 / **角色面板的對應同伴卡** / 待處理事項
- **多訊息**：依**時序排列**（最新在最上）；玩家逐則手動點開查看
- **隱藏**：TurnEnd 階段隱藏，下回合 MapExpand 重新評估

#### 3.9.4 視覺規格
- 氣泡尺寸：約 240 × 60 px
- 圓角邊框 + 半透明背景
- 文字最多 2 行，超出以「…」截斷
- 重要訊息（紅色高亮）優先顯示

### 3.10 死亡與重生機制

#### 3.10.1 觸發條件
主角 HP 降至 0 時觸發，無論發生於戰鬥內（§3.8）或戰鬥外（如事件懲罰、地塊環境傷害）。

#### 3.10.2 重生擲骰規則
- **一局僅 1 次**重生機會
- 擲骰：純 **2d6**，**無屬性加成、無裝備加成、無同伴輔助**
- TN：由序幕卡 `setupRules.respawnRoll.tn` 規定（範例值：7）
- 結果：
  - **成功**（骰點 ≥ TN）：退回**初始地塊（4,4）**、HP 重置為 **1**、ORBIT 軌道狀態保留、回合數不變
  - **失敗**（骰點 < TN）：觸發**失敗結局**（依模組結局卡定義的「重生失敗」結局，§3.12）
- **已用過重生**：再次 HP=0 直接觸發失敗結局，不再擲骰

#### 3.10.3 視覺與時序

**主回合中觸發**（如事件懲罰、地塊環境傷害）：
1. 觸發時暫停其他互動
2. 中央上方判定區顯示骰子動畫（~2 秒，比一般判定略長以強調戲劇性）
3. 結果顯示後自動繼續流程：
   - 成功 → 移動動畫退回初始地塊 → 主角 HP=1 → 進入下回合
   - 失敗 → 切入結局結算（§3.12）
4. TurnLog 記錄結果

**戰鬥中觸發**（Phase C 受擊 HP 歸零）：
1. 主角 HP 降至 0 → **戰鬥子場景暫停所有動畫與互動**
2. 中央上方判定區出現重生擲骰動畫（~2 秒）
3. 結果顯示後：
   - **成功** → 戰鬥子場景淡出（300 ms）→ 主場景淡入（500 ms）→ 主角位於 (4,4) HP=1；該戰鬥卡視為未完成（§3.8.11）
   - **失敗** → 戰鬥子場景淡出（300 ms）→ 切換到結局結算畫面（§3.12）
4. TurnLog 記錄結果

#### 3.10.4 對應 Core 服務
`RespawnService.AttemptRespawn(setupRules.respawnRoll)` →
- 成功：`MapService.TeleportTo(initialTilePos)` + `CharacterService.SetHp(1)`
- 失敗：`EndingService.TriggerFailureEnding("respawn-failed")`

### 3.11 持續效果系統

#### 3.11.1 效果類型
| 類型 | 來源 | 範例 |
|------|------|------|
| **裝備被動** | 已裝備的裝備卡（非背包） | 「破舊長袍：每回合 Draw 階段 +1 探索屬性」 |
| **buff / debuff** | 事件、行動卡、戰鬥效果 | 「狂熱：3 回合內戰鬥傷害 +2」 |
| **地塊環境效果** | 玩家所在地塊 | 「水地塊：移動消耗 +1」「暴風雨地塊：判定 -2」 |

#### 3.11.2 觸發時機（`triggerPhase`）
| 時機 | 適用場景 |
|------|---------|
| `onAcquire` | 效果生效當下執行 1 次（如即時 +5 HP） |
| `drawPhase` | 每回合 Draw 階段開頭評估 |
| `actionPhase` | Action 階段開頭評估 |
| `eventCheck` | EventCheck 階段開頭評估 |
| `turnEnd` | TurnEnd 階段評估（與計時衰減同步） |
| `onTileEnter` | 玩家進入該地塊時觸發 |
| `onCombatHit` | 戰鬥中受擊時觸發 |

#### 3.11.3 計時單位（`duration`）
| 單位 | 衰減規則 |
|------|---------|
| `permanent` | 永久（如裝備被動，移除裝備才失效） |
| `turns:N` | N 個回合，每回合 TurnEnd 時 -1，歸零移除 |
| `phases:N` | N 個階段（更精細的計時） |
| `untilCondition` | 直到 JsonLogic 條件滿足才移除 |
| `untilTrigger:N` | 觸發 N 次後移除（如 vulnerable 受擊 1 次後消耗） |

#### 3.11.4 條件支援
- 效果可附 `enableCondition`（JsonLogic，§7.3）
- 條件不滿足時**暫停效果但不移除**（如「白晝才生效」）
- 條件再次滿足時自動恢復

#### 3.11.5 Stacking 疊加模式（`stacking`）

當同一目標被同名效果重複觸發時，依 `stacking` 欄位決定行為：

| 模式 | 行為 | 適用場景 |
|------|------|---------|
| `add` | **疊加數值**，duration 各自計時 | 一般 buff/debuff（如「+2 攻擊傷害」可疊加成 +4） |
| `replace` | **覆蓋舊效果**（重置 duration 與數值） | 狀態旗標型（如 `vulnerable` 不疊加，每次觸發只是覆蓋） |
| `max` | **取較強者**（數值與 duration 各自取較大值） | 互斥型（如多種「移動 +2」buff 只取最強） |
| `refreshDuration` | **同名僅延長 duration**，不疊加數值 | 持續減益（如「中毒 3 回合」再次觸發只刷新時長） |

**預設**：未指定 `stacking` 時，視為 `add`（最寬鬆）。

#### 3.11.6 範例

**地塊環境效果（暴風雨減益）**：
```json
{
  "id": "storm-tile-debuff",
  "triggerPhase": "onTileEnter",
  "duration": "untilCondition",
  "enableCondition": {"==": [{"var": "currentTile.terrain"}, "storm"]},
  "effects": [
    {"add": {"target": "moveCostOverride", "value": 1}},
    {"add": {"target": "rollCheckBonus", "value": -2}}
  ]
}
```

**buff（狂熱）**：
```json
{
  "id": "frenzy-buff",
  "triggerPhase": "onCombatHit",
  "duration": "turns:3",
  "effects": [
    {"add": {"target": "combatDamageBonus", "value": 2}}
  ]
}
```

**戰鬥狀態（vulnerable）** — 由 Encounter double1 / 攻擊 CritFail / 反應 double1 觸發：
```json
{
  "id": "vulnerable",
  "triggerPhase": "onCombatHit",
  "duration": "untilTrigger:1",
  "stacking": "replace",
  "effects": [
    {"add": {"target": "incomingDamage", "value": 2}}
  ]
}
```
- `stacking: replace` → 多來源不疊加，重複觸發只是覆蓋（不延長次數、不增加傷害）
- 受擊 1 次後消耗，戰鬥結束統一移除

#### 3.11.7 對應 Core 服務
`EffectsService.RegisterEffect(effect)` / `EffectsService.TickPersistent(turn)` / `EffectsService.QueryActive(target)`

### 3.12 結局結算流程

#### 3.12.1 觸發來源
- 結局卡 A 類觸發（EventCheck 階段，§3.4.5）
- 失敗條件達成（§3.1.6 TurnEnd）：HP=0 重生失敗、回合 > 30、地圖飽和
- 主角主動退出？目前不提供（須回主選單放棄遊戲）

#### 3.12.2 流程
1. **中斷遊戲**：暫停所有遊戲互動、停止 ORBIT 處理 queue、停止持續效果計時
2. **顯示結局畫面**（全螢幕）：
   - 結局插圖（`ending.json` 的 `art` 欄位）
   - 結局敘述（`endingText`，可分多頁，玩家手動翻頁；可跳過）
3. **顯示統計面板**：
   - 結局評等（S/A/B/C 大字置中）
   - 總回合數、解算事件數、貢獻分數、戰鬥勝負次數
   - 已揭露結局清單（用於收集要素，未揭露的以 `???` 顯示）
4. **玩家操作選項**：
   - 「回主選單」→ 清空當前 GameState（保留模組與設定）→ 進入主選單
     - **自動存檔保留**：下次選「繼續」會載入結局前一回合的快照
     - 玩家可主動清除自動存檔（系統選項內）
   - 「開新局」→ 同模組重新開始 → 進入序幕卡
   - 「查看存檔」→ 開啟存檔列表（不可繼續本局）

#### 3.12.3 對應 Core 服務
`EndingService.TriggerEnding(endingCard)` →
1. 凍結 GameState
2. 計算統計資料 `EndingService.ComputeStats()`
3. 通知 UI 切換至結局場景 `lifecycle_changed(LifecyclePhase.Ending)`
4. UI 完成後 `EndingService.ReturnToMainMenu()` 或 `GameLifecycle.Restart()`

## 5. 子系統詳細規格

### 5.1 主地圖（Main Map）

#### 5.1.1 渲染參數
```
viewBox:        560 × 400 px（可依視窗縮放）
visibleRows:    5（從近到遠）
visibleCols:    5（左右各 2 欄）
vanishingPointY: 130
groundY:        400
fovHalfWidth:   150
```

#### 5.1.2 投影公式
```
t = depthIndex / maxDepth          # 0=最近, 1=最遠
y = vpY + (groundY - vpY) * t²     # t² 使深度感更自然
cellWidth = (fovHalfWidth * 2) * t / visibleCols
cellHeight = 漸進縮小至 ~30% 起始大小
```

#### 5.1.3 地塊視覺結構
- **頂面**：地形紋理 + 邊框
- **正側面**：模擬卡片厚度（高度 ~8% 格高）
- **暗側面**（可選）：陰影感加強
- 未探索地塊顯示卡背，探索後翻轉動畫

#### 5.1.4 互動

##### Hover / Click 基本行為

| 動作 | 行為 |
|------|------|
| Hover（一般） | 該格亮度 +25%，游標 pointer |
| Hover（移動模式中） | 若還有免費移動格數或剩餘 AP，顯示最短路徑預覽 + AP 消耗 |
| Click（一般，角色所在格） | 彈出「玩家行動觸發器」浮動視窗（§3.9） |
| Click（移動模式中） | 跳出「確認移動到此地塊？」對話框 |
| Click（地塊放置模式中） | 將持有地塊放置於該格（必須為合法 4 方向相鄰未鋪格） |
| Click（小地圖） | 高亮對應格，**不會移動視野** |
| 中鍵拖曳 | 自由偏移視野（不移動角色）；用「回到玩家中心」按鈕重置 |
| 右鍵 | 取消當前模式（移動預覽 / 地塊放置） |
| 移動動畫 | 玩家 + 攝影機同步插值 280–320 ms |
| 抵達後 | 翻開未探索地塊 → 若停留則觸發事件系統（經過不觸發） |

##### 移動完整流程（重申）
1. Action 階段，玩家點擊角色所在格 → 彈出「玩家行動觸發器」
2. 玩家點觸發器中的「移動」 → 觸發器隱藏，進入**移動模式**
3. 滑鼠 hover 任一目標格：
   - 若超出可移動距離：無反應
   - 若在可移動距離內：顯示**最短路徑**線條 + AP 消耗預估
4. 玩家點擊目標格 → 跳出「確認移動到此地塊？」對話框
5. 玩家確認 → 執行移動動畫；玩家取消 / 按右鍵 → 退出移動模式回到 Action

##### 地塊放置流程（MapExpand 階段）
1. 系統取出地塊卡並進入**地塊放置模式**
2. 主地圖所有合法可放置區（與已放置地塊相鄰的空格）高亮顯示
3. 玩家點擊持有地塊 → 卡片進入「待放置」浮動狀態
4. 玩家點擊任一高亮區 → 地塊翻開到該格
5. 不允許旋轉地塊；地塊功能上無方向差別

#### 5.1.5 資料介面
```csharp
class TileData {
    int Row, Col;
    TerrainType Terrain;             // forest / path / grass / water / mountain / building
    bool IsExplored;
    bool HasEvent;
    bool IsEntrance;
    bool Passable;
    int Modifier;                    // 判定修正 +1/0/-1

    // —— 地塊變化功能（§3.5.3）——
    string? TileCardId;              // 該格上目前放置的地塊卡 ID
    string? TransformedFrom;         // 由哪張地塊卡變化而來（null = 原始放置）
    List<TileTransformRule>? Transformations;  // 此地塊可能的變化規則（從 tile.json 載入）
}

class TileTransformRule {
    string TriggerEventId;           // 觸發此變化的事件 ID
    string TransformsTo;             // 變化後的地塊卡 ID
    JsonElement? Condition;          // JsonLogic 條件式（§7.3），null = 無條件
}

class WorldMap {
    int Width = 9, Height = 9;
    TileData[,] Tiles;
    (int Row, int Col) PlayerPos;
    (int Row, int Col) CameraPos;
    event Action<TileData> TileChanged;
    event Action PlayerMoved;
    event Action<TileData, string> TileTransformed;  // (新地塊, 由哪個事件觸發)
}
```

### 7.1 JSONSchema（10 支）
| Schema | 用途 | 備註 |
|--------|------|------|
| `manifest.json` | 模組元資訊 | |
| `prologue.json` | **序幕卡**（§3.4.4） | 含 `prologueText` / `initialGoals` / `victoryConditions` / `failureConditions` / `setupRules`；每模組 1 張 |
| `event.json` | 事件卡 | 含 `triggerBattle`（帶出戰鬥卡）、`transformTile`（觸發地塊變化）等效果欄位 |
| `battle_card.json` | 戰鬥卡 | 對應 `BattleCard`：EnemyStats / EncounterTn / EnemyActions / LootEffects（詳見 §3.8.2）。**v1.1 改名**：舊版為 `battle.json`，移植時 schema 檔名需更新 |
| `tile.json` | 地塊卡 | 含 `transformations` 欄位定義變化規則（詳見 §3.5.3、§5.1.5） |
| `action_card.json` | 行動卡 | 含 `combat` 物件欄位（戰鬥可用標記、`route` = `RollBonus`/`DamageMultiplier`、加成數值），詳見 §3.8.9 |
| `equipment.json` | 裝備卡 | 含 `slotType`（可放入的裝備格類型）+ `combatStats` 物件（武器：`weaponHitBonus` / `weaponDamage`；盾：`shieldHitBonus`；足部：`skillBonus`） |
| `character.json` | 角色（主角） | 含 `combatAbilities` 陣列（每戰冷卻技能，每項含 `route` / `rollBonus` / `damageMultiplier`），詳見 §3.8.9 |
| `npc_companion.json` | NPC 同伴 | 含 `hp` / `ap`（=2）/ `combatSupport`（攻擊加乘 / 行動輔助 / 抵擋傷害 三選一固定設定，戰鬥中自動執行）/ 主動與被動技能設定，詳見 §3.8.12 |
| `ending.json` | **結局卡**（§3.4.5） | 含 `endingType` / `endingText` / `revealCondition` / `triggerCondition` / `scoreCalculation`；每模組可多張對應不同結局 |

**地塊變化規則存放位置**：在 `tile.json` 的 `transformations` 陣列中，每筆規則含：
```json
{
  "triggerEventId": "fire-spreads",
  "transformsTo":   "scorched-earth",
  "condition": {
    "and": [
      {"==": [{"var": "currentTile.terrain"}, "forest"]},
      {"==": [{"var": "flag.fire_started"}, true]}
    ]
  }
}
```
`condition` 採 JsonLogic 表達式（§7.3）；不需要新增獨立 schema 檔案，沿用 `tile.json` 即可。

### 7.3 條件 DSL（JsonLogic）

#### 7.3.1 採用方案
- 使用業界開源規範 [JsonLogic](https://jsonlogic.com/)
- C# 實作：NuGet 套件 `JsonLogic.Net`
- 用於：地塊變化條件（§3.5.3、§5.1.5）、ORBIT 事件揭露/觸發條件（§3.6）、事件選項條件、勝利/失敗條件等

#### 7.3.2 變數命名空間（context 註冊）

| 命名空間 | 內容 | 型別 |
|---------|------|------|
| `flag.<name>` | 全局劇情旗標 | bool |
| `hero.hp` / `hero.maxHp` / `hero.ap` / `hero.maxAp` | 主角狀態 | int |
| `hero.attr.combat` / `.exploration` / `.social` / `.knowledge` | 主角 4 屬性 | int |
| `hero.equipment` | 主角裝備清單（裝備卡 ID 陣列；含 `contains` 判定） | string[] |
| `companion[i].hp` / `companion[i].id` | 同伴 i 的狀態 | int / string |
| `companion.count` | 隊伍中同伴數量 | int |
| `turn` | 當前回合數（從 1 開始） | int |
| `currentTile.terrain` / `currentTile.row` / `currentTile.col` | 玩家所在格屬性 | string / int |
| `currentTile.tileCardId` | 當前地塊卡 ID | string |
| `tile[r,c].terrain` / `.isExplored` | 指定座標地塊屬性 | string / bool |
| `orbit.A.count` / `orbit.B.count` / `orbit.C.count` | ORBIT 軌道事件數量 | int |
| `orbit.contains(<eventId>)` | 軌道是否包含某事件 | bool |
| `worldFlags.<name>` | 環境效果旗標（如暴風雨擴散階段） | any |

#### 7.3.3 支援運算符（JsonLogic 標準）

| 類別 | 運算符 |
|------|--------|
| 比較 | `==` `!=` `<` `<=` `>` `>=` |
| 邏輯 | `and` `or` `!`（not） |
| 算術 | `+` `-` `*` `/` `%` |
| 集合 | `in` `contains` |
| 條件 | `if`（三元：`{"if": [cond, then, else]}`） |
| 變數存取 | `var`（`{"var": "hero.hp"}`） |
| 字串 | `cat`（串接） |

#### 7.3.4 範例

**範例 1**：地塊變化（森林被火災變焦土）
```json
{
  "and": [
    {"==": [{"var": "currentTile.terrain"}, "forest"]},
    {"==": [{"var": "flag.fire_started"}, true]}
  ]
}
```

**範例 2**：事件揭露（探索 ≥ 4 且回合 ≥ 5）
```json
{
  "and": [
    {">=": [{"var": "hero.attr.exploration"}, 4]},
    {">=": [{"var": "turn"}, 5]}
  ]
}
```

**範例 3**：複合條件（已遇女巫且知識 ≥ 4，或持有護身符）
```json
{
  "or": [
    {"and": [
      {"==": [{"var": "flag.met_witch"}, true]},
      {">=": [{"var": "hero.attr.knowledge"}, 4]}
    ]},
    {"contains": [{"var": "hero.equipment"}, "amulet-of-warding"]}
  ]
}
```

**範例 4**：HP 警戒（主角 HP 比例 ≤ 30%）
```json
{"<=": [
  {"/": [{"var": "hero.hp"}, {"var": "hero.maxHp"}]},
  0.3
]}
```

#### 7.3.5 Schema 整合

在各 JSON Schema（`tile.json` / `event.json` 等）中，條件欄位採用統一定義：
```json
"condition": {
  "$ref": "#/definitions/jsonLogic",
  "description": "JsonLogic 條件式，詳見 §7.3"
}
```

`jsonLogic` 定義為通用規則陣列，由 `JsonLogic.Net` 在 runtime 解析。

#### 7.3.6 開發注意
- **熱重載安全**：條件純資料，模組重載後條件即時生效
- **錯誤處理**：條件評估失敗（如變數不存在）回傳 `false`，並記錄 warning
- **效能**：條件評估在 EventCheck / MapExpand 階段觸發，不在每幀計算；可忽略 overhead
- **單元測試**：建議為每個劇情模組的條件撰寫 xUnit 測試（給 fake context 驗證 true/false）

### 7.4 存檔格式
- 使用 Godot `ConfigFile` 或 JSON
- **自動存檔**：每回合 TurnEnd 階段 1 次（覆蓋自動存檔槽）
- **手動存檔**：透過 §4.1 #6 系統選項按鈕內進入；提供 3 個手動存檔槽
- **手動讀檔時機**：
  - **主選單**：可直接進入「讀取存檔」介面選擇任一存檔載入
  - **遊戲中**：透過 §4.1 #6 系統選項 → 「讀取存檔」；僅可在 **Action 階段**立即生效；其他階段（MapExpand / Draw / EventCheck / TurnEnd）排隊至下一個 Action 階段執行
- **存檔內容必含**：
  - 當前 GameState 序列化（HP/AP/手牌/裝備/位置）
  - 回合數、隨機種子、模組 ID
  - **ORBIT 軌道狀態**（已揭/未揭、條件評估快照）
  - **地塊變化歷史**（哪些格子曾發生 transformTile）
  - **同伴 AI 內部狀態**（戰鬥輔助配置、AP 餘量等）
  - **重生擲骰使用狀態**（§3.10，是否已用過）
  - **持續效果清單**（§3.11，含剩餘計時）
  - **已揭露結局清單**（用於收集要素統計）
