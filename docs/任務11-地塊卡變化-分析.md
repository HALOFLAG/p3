## 2. M-series 後端與 WorldMap 的差異盤點

| 維度 | WorldMap（runtime 現用） | GameState（M-series 後端） | 衝突點 |
|---|---|---|---|
| 座標系 | 9×9 固定，玩家起點 (4,4) | 無界 `Dictionary<(int X, int Y), PlacedTile>`，起點 (0,0) | 🔴 全 UI / 投影 / 攝影機都依賴 9×9 bounds |
| 回合命名 | `Turn 1..30`、ApMax=3 | `CurrentBigRound 1..MaxBigRounds`（從 module）、ActionPoints=3 | 🟡 命名不同；TopBar / TURN LOG 顯示要改 |
| 玩家數 | 單一玩家 (`PlayerPos`) | `Players: List<PlayerState>`、`CurrentPlayer` | 🟢 **鎖定單人**：`state.Players[0]` 永遠是 currentPlayer（任務 11 不開多人；後續 Phase 3+ 才考慮） |
| 地形模型 | `MapTerrain` enum（6 種） + PNG 表 | `Tile.Terrain` string（"town"/"wilderness"/...） + `TileId` 路由到 module.Tiles | 🔴 渲染層需要 `TileVisualProfile`：以 **TileId** 為 key 對應 (MapTerrain enum, minimapColor, sceneTheme)，不能只用 terrain string（一對多衝突，例：wilderness 可能涵蓋 forest/swamp/desert） |
| 地塊資料 | `TileData(Row, Col, Terrain, IsPlaced, IsExplored)` immutable | `PlacedTile { TileId, Level, ProgressGainedThisBigRound, ... }` mutable | 🟡 IsExplored ↔ Level（Unknown/Unfamiliar/Familiar/...） 需對應 |
| 卡牌系統 | `WorldMap._hand`、`_actionDeck`、`_companions`、`_equipped` | `PlayerState.Hand/Deck/Discard/Equipment` + `CompanionState` | 🔴 Task 7 卡牌系統雙寫；要選定權威來源 |
| 互動模式 | `InteractionMode { Idle, MapExpand, Move }` | `TurnPhase { Draw, MapExpand, Action, EventCheck, TurnEnd }` | 🟡 Mode 概念不同層級 |
| 事件 | `WorldMap.TileChanged/TilePlaced/HpChanged/...` 一堆 .NET event | GameState **沒有** event；mutation 後由 service 主動 emit | 🔴 UI 訂閱模式要全改 |
| Module 載入 | 沒有 — 起手地塊 hard-code in WorldMap.cs | `ModuleLoader.Load(modulePath)` → `Module` → `GameState.CreateNew(module, characters, companions, seed)` | 🟢 ModuleLoader 已成熟 |

🔴 = 高衝突（重大改寫） / 🟡 = 中衝突（介面調整） / 🟢 = 低衝突（直接接）

## 3. 目標架構（Migration 後）

```
MainBootstrap._Ready
├─ ModuleLoader.Load("modules/builtin/abandoned-mansion") → Module
├─ GameState.CreateNew(module, [hero], [companion], seed) → GameState
├─ TurnLoop(state, module, services)  ← 取代 WorldMap 的回合驅動
├─ EventResolver / EventOrbitResolver / EffectHandler / EffectsService
└─ MainMap (= WorldMap façade) 訂閱 GameState 變化 emit Godot Signal

WorldMap 角色重定位：
  舊：authoritative 9×9 game state
  新：thin façade / projection — 包 GameState 提供 9×9 bounded view + MapTerrain 翻譯 + 既有 .NET event
```

**關鍵設計**：保留 `WorldMap` API surface（給已寫好的 MainMapRenderer / MinimapRenderer / LeftPanel / HandDock 用），內部改成讀 `GameState`。Mutation 全走 GameState，WorldMap 在 service callback 裡 emit 對應 .NET event。

### Stage 2 — WorldMap 改 façade（讀路徑 + 雙寫過渡）

> **修訂說明**：原版只切 getter，會造成「getter 讀 GameState、mutation 仍改 WorldMap」的半同步狀態（UI 顯示舊值或錯值）。改成雙寫過渡：mutation 同時寫 WorldMap 內部 state 與 GameState，保持 Stage 2 結束時可獨立穩定運行。Stage 3 才把 WorldMap 內部 state 移除（純 façade）。

| 軸 | 內容 |
|---|---|
| **方向** | WorldMap getter 改讀 GameState；既有 mutation 暫時雙寫（既寫 `_hand` 也寫 `state.CurrentPlayer.Hand`）讓 Stage 2 為穩定 intermediate |
| **方式** | 1) **Getter 切換**：`WorldMap.PlayerPos => (state.Players[0].Position.Y, state.Players[0].Position.X)`（單人鎖定 Players[0]）、`GetTile(r, c) => TileVisualProfile.Resolve(state.TileMap[(c, r)], module)` 翻譯成 `TileData`、`Hand/Hp/HpMax/Ap/Turn` 全部改讀 GameState；<br>2) **建 `TileVisualProfile`（精細路線）**：tile.json 加 `visualProfile: { terrain: "Forest", minimapColor?: "#3a6830", sceneTheme?: "forest-day" }` 選用欄位；ModuleLoader 解析；逐個替 14 個 tile 補 visualProfile；fallback 表保留作為缺欄位的安全網（wilderness→Forest / town→Building / road→Path / field→Grass / water→Water / mountain→Mountain）；<br>3) **Mutation 雙寫**：`TryPlaceHeldTile` / `TryConsumeAp` / `TryPlayCard` 等 mutation 在原邏輯後加 `MirrorToGameState()` 把該動作鏡射到 GameState（不走 service，純資料 mirror）；<br>4) **既有 .NET event 仍由 WorldMap 自己 emit**（順序不變，UI 訂閱沿用）；<br>5) `Companions` 從 state.Companions + module.NpcCompanions 組合 |

### Stage 3 — WorldMap 純 façade（寫路徑 + 事件排序層）

> **修訂說明**：原版只說「service emit → WorldMap 再 emit」，但漏了**事件順序一致性**問題：UI 訂閱常隱性依賴 WorldMap 既有事件順序（如 `PlayerMoved` 在 `ApChanged` 之前），改走 service 後順序可能反轉，產生偶發 UI bug（最難 debug 的那種）。WorldMap 不只是 façade，要兼任 **Event Adapter + Order Controller**：把 service 散發的事件 buffer 起來，按 UI-safe 順序重排再 emit。

| 軸 | 內容 |
|---|---|
| **方向** | 移除 WorldMap 內部 state（_hand / _equipped / _companions / 等），mutation 只走 GameState；同時加事件排序層保證 UI 訂閱順序穩定 |
| **方式** | 1) **Mutation 改派**：`TryPlaceHeldTile` → `MapService.ExpandTile(state, ...)`、`TryConsumeAp` / 移動 → TurnLoop / Action 路徑、`TryPlayCard` → 走 GameState.Hand 操作；<br>2) **刪除 WorldMap 內部 state**：`_hand` / `_equipped` / `_actionDeck` / `_companions` / `_character` 等全砍，全改 GameState 讀寫；<br>3) **Event Adapter**：建 `WorldMapEventBuffer` — service 層 mutation 完成後不直接 emit，而是把事件記入 buffer，由 WorldMap 在 mutation 邊界（method 結束、事件解析結束）按固定順序 emit：`TileChanged → TilePlaced → PlayerMoved → HpChanged → ApChanged → HandChanged → ModeChanged → CompanionChanged`（依 UI 訂閱依賴度排）；<br>4) **ORBIT 結算接上**：當前 [MainBootstrap.cs:321](scripts/MainBootstrap.cs#L321) TODO 點改呼叫 `EventResolver.ResolveEvent(state, card)` → 套 outcome.Effects 走 EffectHandler；effects 套用過程透過 buffer 累積、結束後一次 flush 給 WorldMap 重排 emit |
| **目標** | 操作真正改 GameState；UI 訂閱順序與 Phase 1+2 一致 |
| **成果** | 端到端「行為一致性」恢復；EventResolver / EffectHandler 自動跑；UI 無偶發順序 bug |
| **風險** | 🔴 既有 WorldMap mutation 行為要與 TurnLoop 對齊（特別 `_actionDeck.Draw()` vs `TurnLoop.DoDraw`）；<br>🔴 Phase 1+2 P0 完整探索流程（任務 6）不能爆 — Stage 3 結束立即跑 L3-01 happy path 把關，不過就 rollback；<br>🔴 既有 355 個 xUnit 中對 WorldMap mutation 的測試需重新指派為 façade 測試或 GameState 測試；<br>🟡 Event order 規則文件化（在 `WorldMapEventBuffer` 註解列出 canonical order），避免未來新事件插入時打破依賴；<br>🟡 EventBus（Task 9）信號要對齊 EventResolver — 統一所有 ORBIT 事件走 EventResolver，EventBus 只做 UI signal bridge |
| **工時** | 6-9 h |

### Stage 5 — Tile transform rules schema + EventCheck 階段觸發

> **修訂說明**：原版「事件 trigger 後遍歷 9×9 tile 呼叫 TryTransformTile」是 O(81 × R) per event。9×9 還能擋，但設計時就該避免 — 改用 **event-indexed transform registry**：模組載入時建 `Dictionary<EventId, List<TileTransformRule>>`，事件觸發只查該 event 訂閱清單，O(R)。未來 Task 14 地圖擴大或 transformation 多時直接受惠。

| 軸 | 內容 |
|---|---|
| **方向** | `transformTile` 從 event outcome 變到 tile 自身規則（§1.5 `TileTransformRule`），並建 event-indexed registry 避免 O(n²) |
| **方式** | 1) `tiles.json` 加 `transformations: [{ triggerEventId, transformsTo (tileId), condition? (JsonLogic) }]` 選用欄位；<br>2) `Tile` model 加 `Transformations: List<TileTransformRule>`；<br>3) **建 `TileTransformRegistry`**：模組載入時掃所有 tiles 的 transformations，建 `Dictionary<EventId, List<(TileId SourceTileId, TileTransformRule Rule)>>`；<br>4) `MapService.TryTransformTile(state, module, row, col, triggeredEventId, jsonLogicCtx)` — 從 registry 查 triggeredEventId 對應的規則清單，掃 `state.TileMap` 找 TileId 符合 SourceTileId 的格、評估 condition，符合則 `EffectHandler.ApplyTransformTile` 套 `TransformTileEffect{NewTileId=rule.TransformsTo}`；<br>5) EventResolver 在事件 trigger 後**僅查 registry 一次**呼叫 `TryTransformTile`（不遍歷整張地圖）；<br>6) 起始模組 `tiles.json` 加 1-2 個 demo（如 `forest-path` 在 `fire-spreads` 事件 → `forest-burnt`，需新增 `forest-burnt` tile 條目） |
| **目標** | 規格 §1.5 的 tile-side transformation 完整；轉變查找 O(R) 不 O(n×R) |
| **成果** | L1 `MapService_TryTransformTile_PreservesPositionAndExplored / ConditionFalse_NoChange` 通過 |
| **風險** | 🟡 module schema 升級（需要 JSON schema 的 transformations 欄位；ModuleLoader 解析）；<br>🟡 既有 `forest-path` tile 沒有 `forest-burnt` 對應紋理 — 美術未到位先用 `forest-path` 自身或備用色塊；<br>🟢 registry 是不可變字典，模組載入後 read-only — thread-safe 直接 ok |
| **工時** | 3-4 h |

## 9. 修訂紀錄

### v2 — 技術審查修訂

針對原版 5 個技術盲點修正：

| 盲點 | 原版做法 | 修訂後做法 | 影響 |
|---|---|---|---|
| **Stage 2 半同步狀態** | 純 getter 切換 → mutation 仍寫 WorldMap → getter 讀 GameState → UI 顯示舊值 | 雙寫過渡：mutation 同時寫兩邊，Stage 2 結束時可獨立穩定運行 | Stage 2 工時 +1h；新增 `MirrorToGameState()` helper |
| **Stage 3 事件順序不一致** | service 散發事件 → WorldMap 直接轉發 → 順序可能反轉 → 偶發 UI bug | 加 `WorldMapEventBuffer` 排序層：buffer + reorder + emit by canonical order | Stage 3 工時 +1-2h；新增事件序列文件化 |
| **MapTerrain 翻譯一對多** | terrain string → MapTerrain enum（wilderness→Forest），但 wilderness 涵蓋 forest/swamp/desert 視覺撞色 | 改用 `TileVisualProfile`：keying by **TileId**（不是 terrain string），fallback 才走 terrain mapping | 設計修正、工時持平；schema 加 visualProfile 選用欄位 |
| **Stage 5 O(n×R) 遍歷** | 事件觸發遍歷 9×9 tile 對每格檢查 transformations | 建 `TileTransformRegistry`：模組載入時索引 `Dictionary<EventId, List<TileTransformRule>>`，O(R) 查找 | Stage 5 工時持平甚至略省；未來地圖擴大不爆 |
| **Stage 7 EffectsService 偷做** | 直接讀 `apCostBonus` / `rollBonus` 欄位 → Task 13 完整 EffectsService 時被重寫 | 抽 `ITileEffect` 介面，兩個實作（ApCostBonus / RollBonus），Task 13 加實作即可 | Stage 7 工時 +0.5h；省 Task 13 重寫成本 |

**淨工時影響**：原版 24-31 h → 修訂版 26-35 h（+2-4 h），但避免至少 3 個高機率 bug 與 1 次 Task 13 重寫。
