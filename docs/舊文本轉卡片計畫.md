### 1.2 ActionCard 欄位（規格依據 §1.4 + 實作對齊）

```csharp
// core/Models/ActionCard.cs
public sealed record ActionCard(
    string Id,
    string Name,
    ActionType Type,        // Communication | Combat | Exploration | Thinking
    int Cost,
    IReadOnlyList<string> Tags,
    string Description
)
{
    public int? UsesPerTurn { get; init; }
    public int? UsesPerEvent { get; init; }
    public CombatEffect? Combat { get; init; }   // 可選 DamageMultiplier 或 RollBonus 路線
}
```

### 1.3 Equipment 欄位

```csharp
public sealed record Equipment(
    string Id, string Name,
    EquipmentSlot Slot,                         // Weapon/OffHand/Head/Body/Hand/Feet/AccessoryA/AccessoryB/Utility/Character
    StatBlock? StatBonuses,                     // power/social/skill/intellect
    string EffectText
)
{
    public ItemCategory Category { get; init; } = ItemCategory.Special;
    public IReadOnlyList<EquipmentSlot> AllowedSlots { get; init; }   // 多槽相容
    public WeaponStats? Weapon { get; init; }   // hitBonus / damage
}
```

### 1.4 設計原則（規格書 §1.4 摘要）

- 行動卡：唯一三堆（抽 / 棄 / 移除），抽空自動洗回棄牌堆
- 事件卡：地塊 / 回合 / Flag / 行動次數觸發，進 ORBIT 軌道，**不入手牌**
- 地塊卡：線性序列、MapExpand 階段逐張取出、NEXT 預覽
- 裝備卡：無牌庫，獲得時自動入背包；3×3 + 背包 3
- 戰鬥卡：事件 `triggerBattle` 即時帶出、結束丟棄、勝利結算 `lootEffects`
- 結局卡：揭露 → ORBIT → EventCheck 觸發即結束遊戲
- 序幕卡：每模組 1 張，全螢幕顯示、執行 `setupRules`

### 4.5 同伴卡 / 角色卡 wrapper（α 包裝型別）

`CompanionCard` / `CharacterCard` 是「**之後有其他用途**」的薄包裝（α），把現有 `NpcCompanion` / `Character` 包成卡片表示。卡片本體 (`Id`/`Name`/`Description`/`PortraitPath`) 可獨立持久化、進 deck / collection / 圖鑑；遊戲性資料 (`Stats`/`Hp`/`StartingDeck` 等) 仍由 `Companion` / `Character` 欄位指向原實體取得。

```csharp
// 同伴卡：包裝 NpcCompanion
new CompanionCard(
    Id:          "card-priest",
    Name:        "神父",
    Description: "破敗教堂的老牧者，能在混亂中為同伴穩住心神。",
    Companion:   module.NpcCompanions["priest"]
) { PortraitPath = "art/companions/priest.png", Tags = new[] { "support" } };

// 角色卡：包裝 Character
new CharacterCard(
    Id:          "card-scholar",
    Name:        "學者",
    Description: "對禁忌典籍的執著大過自身安危。",
    Character:   module.Characters["scholar"]
) { PortraitPath = "art/characters/scholar.png", Tags = new[] { "lore" } };
```

> 目前**沒有**獨立 `*.json` 載入流程；wrapper 由 UI 端在開新局選角 / 招募 / 圖鑑顯示時即時組裝。如未來要把卡片本體寫入存檔（例如「玩家蒐集到的同伴卡圖鑑」），再加 schema 不遲。

## 5 · 已決議事項（A1-A4 / B1-B2，2026-04-26）

### A1 · 序幕 turnLimit
**保留現行 30 回合**。`prologue.json` 與開場敘事不需改動。

### A2 · 「陷阱 / 環境 / 同伴卡」是否新增類別
**移除陷阱相關內容**，並**新增同伴卡 / 角色卡**兩個 α 包裝型別：
- 陷阱：本文件已移除「拆除陷阱」action card 範例與相關討論；現行 events.json 失敗分支 + Tile.onEnter 已足以表達既有陷阱情境，未來不再以「陷阱」為一個類別來規劃
- 同伴卡 `CompanionCard`、角色卡 `CharacterCard`：見 §4.5；之後若有「圖鑑 / 招募 / 收集」等用途可直接擴充

### A3 · clue / oil / herb 資源是否獨立成 resources.json
**移除相關內容**（屬舊版本資料）。本文件範例已不再示範資源 catalog；如未來真的需要，再單獨設計 `Resource` schema 即可。

### A4 · 本文件可否上 GitHub
**可**。`docs/舊文本轉卡片計畫.md` 上傳 GitHub；`oldplan_p2/` 原檔仍依 `.gitignore` 排除。

### B1 · ORBIT JsonLogicContext 變數路徑
**`orbit.contains.<eventId>`** 採布林 flag 寫法（已實作於 `core/Services/JsonLogicContextBuilder.cs`）。`tile[r,c].*` lazy resolver **獨立 PR**，不在本次範圍。

### B2 · EndingCard schema 是否擴 revealCondition / triggerCondition
**選方案 X（不擴）**。`core/Models/Ending.cs` 維持「分數門檻」單一規則；條件結局留待實際劇本（Phase 3 Task 14）有需求時再擴。Agent B 的 `EventInstance` wrapper 已預留擴展能力，不擴 schema 也能跑「未來想要的條件結局」。
