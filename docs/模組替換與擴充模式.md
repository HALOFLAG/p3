# 模組替換與擴充模式

> 寫於 2026-04-27（commit `7be6bf0` 後）。
> 對應規格書 §5.1 模組系統 + 任務 17 候選功能。
> 解決問題：是否能單獨替換某些卡片 / 序幕卡來影響遊戲？

---

## 1. 兩個情境拆解

| 情境 | 規模 | 實作模式選項 |
|---|---|---|
| **A. 單獨替換某些卡片**（如改部分事件 / 加新結局 / 換戰鬥）| 卡片級別 | Overlay / Patch / Variant |
| **B. 單獨替換序幕卡**（調整難易度 / 勝負條件）| 設定級別 | Multi-prologue / Difficulty preset |

兩者根本上都是「**模組組合（composition）**」的不同粒度。

---

## 2. 三種實作模式（由簡到複雜）

### 模式 1：難度 preset（最簡單）

**思路**：序幕卡內含多個 difficulty preset，玩家選一個 → runtime 套對應參數。

#### Schema 改動

```json
// prologue.json
{
  "moduleName": "廢棄洋房調查",
  "openingNarrative": "...",
  "startingTileId": "village-square",
  "startingCompanionIds": ["old-priest", "hired-bodyguard"],

  "presets": [
    {
      "id": "easy",
      "label": "輕鬆",
      "difficulty": 2,
      "loseConditions": [{ "type": "turnLimit", "value": 40 }],
      "difficultyCurve": {
        "early": { "tnRange": [6, 8] },
        "middle": { "tnRange": [8, 10] },
        "climax": { "baseTn": 12, "perFailureTnIncrease": 1, "tnCap": 15 }
      }
    },
    {
      "id": "normal",
      "label": "標準",
      "difficulty": 3,
      "loseConditions": [{ "type": "turnLimit", "value": 30 }],
      "difficultyCurve": { ... 原值 ... }
    },
    {
      "id": "hard",
      "label": "困難",
      "difficulty": 4,
      "loseConditions": [{ "type": "turnLimit", "value": 25 }],
      "difficultyCurve": {
        "early": { "tnRange": [10, 12] },
        "middle": { "tnRange": [12, 14] },
        "climax": { "baseTn": 16, "perFailureTnIncrease": 2, "tnCap": 20 }
      }
    }
  ],

  "winConditions": [ ... ],  // 共用
  "scoreFormula": "..."       // 共用
}
```

#### 玩家流程

```
F5 → 選擇模組「廢棄洋房調查」→ 選擇難度【標準】→ 進場
                            └ presets 選 normal
```

#### 工時 / 影響面

| 項 | 估時 |
|---|---|
| Prologue model 加 `Presets: List<DifficultyPreset>` | 1 h |
| Schema validation | 30 min |
| 主選單加難度選擇 UI | 2 h |
| ApplyPreset 把 difficulty / loseConditions / TN curve 套到 GameState | 1 h |
| 既有模組 prologue.json 拆出 presets | 30 min |
| **小計** | **5 h** |

**優點**：超直觀，一個模組多種難度。
**缺點**：只能調**設定值**，無法替換具體事件 / 戰鬥內容。

---

### 模式 2：Multi-prologue per module（中等）

**思路**：同個模組目錄下有**多個 prologue 變體**，玩家選哪個 → 載入哪個 prologue.json。

#### 目錄結構

```
modules/builtin/abandoned-mansion/
├── manifest.json
├── prologues/
│   ├── normal.json    ← 預設
│   ├── easy.json
│   ├── hard.json
│   └── nightmare.json ← 噩夢模式：改起始角色為 occultist + 5 同伴限制
├── characters.json
├── ... (其他 8 類卡片相同)
```

#### Manifest 加入 prologue 清單

```json
{
  "id": "abandoned-mansion",
  "name": "廢棄洋房調查",
  ...
  "prologues": [
    { "file": "prologues/easy.json", "label": "輕鬆", "stars": 2 },
    { "file": "prologues/normal.json", "label": "標準", "stars": 3, "default": true },
    { "file": "prologues/hard.json", "label": "困難", "stars": 4 },
    { "file": "prologues/nightmare.json", "label": "噩夢", "stars": 5 }
  ]
}
```

#### 玩家流程

```
F5 → 選模組 → 選 prologue（輕鬆 / 標準 / 困難 / 噩夢）→ 進場
                ↓
                每個 prologue 完全獨立，可換任何 prologue 欄位：
                - 起始角色 / 起始同伴 / 起始地塊
                - 完全不同的勝負條件
                - 完全不同的難度曲線
                - 不同 scoring formula
                - 甚至連 openingNarrative 都不同
```

#### 工時 / 影響面

| 項 | 估時 |
|---|---|
| Manifest 加 prologues 清單 + schema | 1 h |
| ModuleLoader 接受 prologueFile 參數 | 1 h |
| 主選單 prologue 選擇 UI（縮圖卡片風） | 2-3 h |
| 既有模組拆 prologue 變體 | 1 h |
| **小計** | **5-6 h** |

**優點**：序幕卡完全獨立，可大幅改寫劇本起點（不只難度）。
**缺點**：仍綁同一份 cards/tiles/events 內容；無法改具體事件。

---

### 模式 3：Module overlay / extends（最強，最複雜）

**思路**：模組可宣告「**繼承**」另一個模組，並**選擇性覆寫**部分卡片。

#### Manifest 加 extends 欄位

```json
// modules/community/abandoned-mansion-extra/manifest.json
{
  "id": "abandoned-mansion-extra",
  "name": "廢棄洋房調查 - 擴充劇情包",
  "extends": "abandoned-mansion",  ← 繼承基礎模組
  "version": "1.0.0",
  "author": "社群作者"
}
```

#### 此擴充模組的內容

```
modules/community/abandoned-mansion-extra/
├── manifest.json     ← 宣告 extends abandoned-mansion
├── prologue.json     ← 可選：覆寫序幕卡（如改 winConditions 加新條件）
├── events.json       ← 可選：merge 進原本 13 個（用 id 覆寫）
│   └─ [
│       { "id": "village-inquiry", ... },  ← id 已存在 = 覆寫該事件
│       { "id": "haunted-merchant", ... }, ← id 不存在 = 新增該事件
│      ]
├── endings.json      ← 可選：可加 1-2 個新結局
└── tiles.json        ← 可選：加新 tile（如「血祭壇」）

(其他 7 類卡片若無檔案 = 完全沿用 base)
```

#### 載入邏輯

```
ModuleLoader.Load(extra)
  → 讀 manifest.json，發現 extends="abandoned-mansion"
  → 先 ModuleLoader.Load(base = abandoned-mansion)
  → 再讀 extra 的各 .json，merge 進 base：
      - 同 id  → 覆寫
      - 新 id  → 新增
  → 跨檔 cross-ref 用 merge 後的資料驗證
  → 回傳組合後的 Module
```

#### 用例

| 目的 | extra 覆寫什麼 |
|---|---|
| 困難模式 | 覆寫 `events.json` 把所有 TN +2，覆寫 `prologue.json` 改 turnLimit 25 |
| 翻譯版 | 覆寫所有卡的 narrative / name 欄位（中文/英文/日文） |
| DLC 擴充劇情 | 加新 events / endings / battles，不動原本 |
| 平衡 patch | 只改幾張卡的 cost / TN / hp，其他不動 |
| 社群同人 | 改 endings 加新結局；改 npc_companions 加新同伴 |

#### 玩家流程

```
F5 → 模組選單顯示樹狀：
   ├── 廢棄洋房調查 [base]
   │   ├── ＋ 擴充劇情包（社群作者）
   │   ├── ＋ 困難模式
   │   └── ＋ 翻譯版（English）
   └── （其他 base 模組）
   
玩家選 base 或 base + extension → 載入組合
```

#### 工時 / 影響面

| 項 | 估時 |
|---|---|
| Manifest schema 加 `extends` 欄位 | 30 min |
| ModuleLoader 加 LoadWithExtensions(...) | 3-4 h |
| Merge 邏輯（id-based override） | 2 h |
| 跨檔 cross-ref validation 處理 merge 後 | 1-2 h |
| 主選單樹狀模組 UI | 4-5 h |
| 文件 / 範例 extension 模組 | 2 h |
| **小計** | **12-15 h** |

**優點**：最強 — 可單獨替換**任意**卡片，社群可寫小型 patch / 翻譯 / DLC。
**缺點**：複雜度高；需 cross-ref 處理 merge edge case；UI 樹狀化。

## 3. 三種模式對比表

| 維度 | 模式 1 難度 preset | 模式 2 multi-prologue | 模式 3 overlay/extends |
|---|---|---|---|
| 改變範圍 | 設定值（TN / turnLimit） | 整個 prologue（含起始陣容） | **任意卡片** |
| Schema 改動 | 小（preset 嵌 prologue 內） | 中（manifest 加 prologues 清單） | 中（manifest 加 extends） |
| Loader 改動 | 小（套 preset 值） | 中（選一個 prologue file） | 大（merge 多模組） |
| UI 改動 | 小（加難度選擇） | 中（加 prologue 卡片選擇） | 大（樹狀模組顯示） |
| 工時 | **5 h** | **5-6 h** | **12-15 h** |
| 適用場景 | 「同模組多難度」 | 「同模組多開場 / 多陣容」 | 「同模組可被任意 patch / 翻譯 / DLC」 |
| 模組製作者門檻 | 低（嵌一個 array） | 低（多寫幾個 prologue.json） | 中（要懂 merge 邏輯 + extends） |

## 4. 推薦實作路徑（漸進式）

依使用者實際需求依序加：

### 第 1 步：模組可替換 runtime（4-6 h，前置條件）

在加任何替換 / 擴充模式前，必須先補完當前 runtime 入口寫死的問題：

| 項 | 估時 |
|---|---|
| `MainBootstrap.DiscoverModules` 掃 modules/ 目錄 | 1 h |
| 主選單模組選擇 UI | 3-5 h |
| 移除 hardcoded fallback（強制 prologue 完整） | 1 h |

完成後玩家才能在 runtime「選擇」任何模組，後續模式 1/2/3 才有意義。

### 第 2 步：模式 1（難度 preset）— **5 小時**

最常見需求：「我想玩同樣劇本但難一點」。

加 prologue.presets 即可，cost-to-value 比例最高。

### 第 3 步：模式 2（multi-prologue）— **+5-6 小時**

當有「我想玩同樣世界但不同陣容開局」的需求，例如：
- 標準模式：scholar + (老神父 + 保鏢)
- 異教徒模式：occultist + (記者 + 老神父)
- 武鬥模式：guard + (保鏢 + 保鏢) — 雙保鏢

### 第 4 步：模式 3（overlay/extends）— **+12-15 小時**

當有社群 / DLC / 翻譯需求，或想做「平衡性更新」而不重發整個模組。

---

## 5. 如果只挑一個做？

**強烈推薦模式 1（難度 preset）**，因為：

1. **5 小時最便宜**
2. 解決最常見的「難度需求」
3. 不影響當前模組結構（既有 abandoned-mansion 只需把 prologue 拆 presets）
4. 模組製作者門檻最低（不必管理多檔 / merge）
5. 可作為**模式 2/3 的基礎**（preset 機制可後續擴展）

模式 2/3 可以等真正需求出現再加（如：玩家社群開始想做 DLC）。

---

## 6. 模式組合與互動性

三種模式**不互斥，可疊加**：

| 組合 | 效果 |
|---|---|
| 1 only | abandoned-mansion 有 3 個難度 preset（基本款） |
| 1 + 2 | abandoned-mansion 有 3 個 prologue 變體 × 每個 3 個難度 = 9 種開局 |
| 1 + 2 + 3 | 上述 9 種 + 社群擴充包（新事件 / 新結局 / 翻譯） |

未來若做齊三種，**單一引擎可支撐近乎無限的劇本變化**。

---

## 7. 設計原則

無論做哪個模式，都應遵守：

### 7.1 模組仍是 immutable data

模組載入後不可變。所有「替換 / 覆寫 / merge」都在**載入階段**完成，產生的 `Module` record 仍是不可變快照。

### 7.2 引擎不變

任何模式都不應要求引擎（C# 程式碼）特殊對待某模組。引擎接受的依然是 `Module` record。

### 7.3 schema 向後相容

新增 `presets` / `prologues` / `extends` 欄位都應為**選用**，舊模組（無這些欄位）依然能被載入。

### 7.4 cross-ref 仍要驗證

模式 3 merge 後的 module 仍需通過 cross-ref 驗證（startingTileId 必須存在 / triggerEventId 必須存在等），確保資料完整性。

---

## 8. 一句話總結

**兩個情境都做得到**：
- ✅ 替換序幕卡調整難易度 → 模式 1（preset）或模式 2（multi-prologue）
- ✅ 單獨替換某些卡片影響情節 → 模式 3（overlay/extends）

**但目前都還沒實作**。runtime 入口寫死一個模組路徑，連模組選擇都還沒做。

**建議實作順序**：
1. 模組可替換 runtime（前置 4-6h）
2. 模式 1 難度 preset（5h）
3. 視需求再加模式 2 / 模式 3

完成 1+2（共 ~10h）即可立即解鎖最常見的多模組多難度體驗。
